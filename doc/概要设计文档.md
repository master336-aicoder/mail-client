# Web 版邮箱客户端概要设计文档

> 版本：v1.0
> 关联文档：`doc/需求分析文档.md`（v1.1）
> 技术栈：Spring Boot 3 + Vue 3（PWA）

---

## 1. 设计目标与原则

### 1.1 设计目标

依据《需求分析文档 v1.1》落实以下已确认关键决策：

| 决策 | 概要设计落点 |
| --- | --- |
| D-1 仅单向导出 PST 供 Outlook 读取 | OST 工作存储 + PST 导出模块（标准 .pst 输出） |
| D-2 实时推送 | IMAP IDLE + WebSocket 推送服务，降级轮询 |
| D-3 不支持 Exchange | 协议层仅 IMAP4 / POP3 / SMTP |
| D-4 附件双存储 | FileStorage 与 MinioStorage 统一抽象，可切换 |
| D-5 PWA 离线 | Vite + vite-plugin-pwa + Workbox 离线缓存 |

### 1.2 设计原则

1. **分层解耦**：展示层 / 接口层 / 业务层 / 协议层 / 存储层，逐层只依赖下层。
2. **可插拔**：协议适配、附件存储、规则引擎均以接口抽象，便于替换与扩展。
3. **每用户隔离**：OST 存储按用户隔离，凭据加密存储，访问严格鉴权。
4. **异步化**：同步、发送、规则、推送均基于消息队列异步执行。
5. **幂等可靠**：同步与规则处理具备幂等性与可重试性。

### 1.3 总体架构

```
+---------------------------------------------------------------------------------+
|                         前端 Layer (Vue 3 + Vite + PWA)                          |
|  登录/账户 | 邮件列表/详情/编写 | 文件夹 | 规则 | 搜索 | 导入 | 设置 | 离线缓存     |
|  (Pinia 状态) | (Vue Router) | (UI 库) | (Workbox Service Worker)                 |
+----------------------------------------+----------------------------------------+
                     | REST(API)                      | WebSocket(推送/实时更新)
+----------------------------------------v----------------------------------------+
|                         接口 Layer (Spring MVC / WebSocket)                       |
|  Controller | DTO | 鉴权拦截器 | 统一异常 | WebSocket endpoint                       |
+----------------------------------------+----------------------------------------+
|                         业务 Layer (Service)                                      |
|  用户 | 账户 | 邮件 | 文件夹 | 规则引擎 | 搜索 | 导入导出 | 实时推送 | 配额          |
+----------------------------------------+----------------------------------------+
|                         协议 Layer                                                 |
|   IMAP4(含 IDLE) | POP3 | SMTP   —— MailClient 接口 + 具体实现                   |
+----------------------------------------+----------------------------------------+
|                         存储/基础 Layer                                            |
|  OST 存储服务(每用户 .ost) | 附件存储抽象(本地/MinIO) | 元数据库 | Redis | MQ      |
+---------------------------------------------------------------------------------+
```

## 3. 数据模型设计（概要）

### 3.1 实体关系概览

```
User 1—N Account 1—N (Folder, Message摘要, Rule...)
User 1—1 OST(工作存储)  附件 存储于 本地/MinIO
```

主要实体：

| 实体 | 说明 | 关键字段 |
| --- | --- | --- |
| users | 平台用户 | id, username, password_hash, mfa_enabled, storage_quota |
| mail_accounts | 绑定的邮箱账户 | id, user_id, email, protocol, host, port, encryption, username, credential_ref |
| folders | 文件夹 | id, user_id, account_id?, parent_id, name, ost_path, unread_count |
| messages(摘要) | 邮件摘要(用于列表/搜索) | id, user_id, account_id, folder_id, message_id/uid, subject, from, to, date, flags, size, ost_ref |
| attachments_meta | 附件元数据 | id, message_id, name, mime, size, store_type(local/minio), path/bucket+key |
| rules | 规则 | id, user_id, name, priority, enabled, conditions(json), actions(json) |
| sync_jobs | 同步任务/日志 | id, user_id, account_id, type, status, last_uid, last_run, result |
| credential_box | 凭据密文 | ref, encrypted_value(iv/nonce/tag), algo |

### 3.2 凭据安全

- 邮箱密码/授权码使用 **AES-256-GCM** 静态加密，主密钥从环境变量/密钥管理服务(KMS)获取。
- 数据库仅存密文与引用（credential_ref）。
- OAuth2/OAuth 授权码流程支持（可选）。

## 4. OST 工作存储设计

### 4.1 存储布局

```
storage/{userId}/mail.ost     # 本用户全部邮件对象(文件夹/消息/附件引用/规则/配置)
storage/{userId}/backup/*.ost # 周期备份
backups/global/               # 全局备份任务
```

### 4.2 OST 内部结构（逻辑）

| 区段 | 内容 |
| --- | --- |
| StoreInfo | 版本、用户、时间戳 |
| FolderTable | 文件夹层级树 |
| MessageIndex | 邮件对象索引(uid/message-id) |
| MessageBody | 邮件正文(MIME) |
| AttachmentRef | 附件引用(指向本地/MinIO) |
| RuleTable | 导出用的规则快照(可选) |
| Metadata | 同步游标(lastUid、latestSync) |

> 实现：自研二进制序列化或基于成熟库封装。托管于 `ost` 存储服务；每次改动加**用户级文件锁**，写后刷盘，异常提供残缺检测与回滚。

### 4.3 PST 导出（D-1）

- 目标：从 **OST 工作存储** 生成 **标准 .pst**，确保 Outlook 2013/2016/2019/365 能打开读取。
- 方案：基于已验证的 Java PST 读写库（如 Apache JAMES 生态 / 社区 Java-PST），在概要设计阶段先做 **POC**；若库不满足则自研 POC 序列化器。
- 导出流程：
  1. 读取用户 OST → 构建内存对象模型(文件夹/消息/附件)。
  2. 附件内容从本地/MinIO 拉取，内嵌进 .pst。
  3. 通过 PST Writer 生成 .pst（符合标准结构）。
  4. 前端下载。
- PST 导入（P1）：解析 .pst → 写入用户 OST（Web 上传，限大小）。

### 4.4 兼容性验证矩阵（概要）

| Outlook 版本 | 打开 .pst | 读取正文 | 读取附件 | 显示文件夹 | 读取规则 |
| --- | --- | --- | --- | --- | --- |
| Outlook 2013 | 验证 | 验证 | 验证 | 验证 | 不承诺 |
| Outlook 2016 | 验证 | 验证 | 验证 | 验证 | 不承诺 |
| Outlook 2019 | 验证 | 验证 | 验证 | 验证 | 不承诺 |
| Outlook 365 | 验证 | 验证 | 验证 | 验证 | 不承诺 |

> 规则(邮件规则)主要在前端/服务端规则引擎执行，不承诺导出到 Outlook 的本地规则（向下兼容 Outlook 规则定义复杂）。

## 5. 实时推送设计（D-2）

### 5.1 推送总体流程

```
邮箱服务器 --(IMAP IDLE 有新邮件消息)--> SyncWorker
   -> 增量拉取新邮件 -> 写入 OST -> 触发规则 -> 发布事件到 MQ
   -> PushService 经 WebSocket 推送到该用户前端 -> 前端刷新
（IMAP IDLE 超时/断开/SELECTED 限制时 -> 降级为配置周期轮询）
```

### 5.2 组件

| 组件 | 说明 |
| --- | --- |
| SyncWorker | 每账户维护 IMAP 连接，进入 IDLE；收到 EXISTS/新消息后增量同步 |
| UidTracker | 记录每个账户/folder 的 lastUid，用于增量 |
| IdleGuard | 心跳(noop/检查间隔)、超时重连、断开重建、降级策略 |
| PushHub | 前端 WebSocket 连接管理器(会话绑定) |
| MQ Topic | `mail.events.{userId}` 主题，解耦同步与推送/规则 |

### 5.3 WebSocket

- 协议：原生 WebSocket 或 STOMP over WebSocket，经 Spring Boot /STOMP Broker + Redis/MQ 广播。
- 鉴权：握手携带 token 校验；连接绑定 userId。
- 心跳：客户端/服务端定时 ping-pong；断线指数退避重连。
- 消息类型：`MAIL_NEW` / `FOLDER_UPDATE` / `FLAGS_CHANGE` / `RULE_TRIGGERED` / `SYNC_STATUS`。

### 5.4 降级策略

- 服务器不支持 IDLE → 定时轮询（配置 1~5 分钟）。
- IDLE 连接被服务端超时 → 重连；失败超过阈值 → 降级轮询，恢复后回切 IDLE。

## 6. 附件双存储设计（D-4）

### 6.1 抽象接口

```java
interface AttachmentStorage {
  StorageRef put(InputStream in, String name, String mime, long size);
  InputStream get(StorageRef ref);
  void delete(StorageRef ref);
  String presignedUrl(StorageRef ref, Duration ttl); // 下载/预览
}
```

两个实现：
- `LocalFileStorage`：存到 `attachments/{userId}/...`，StorageRef = 相对路径。
- `MinioStorage`：上传到 MinIO 桶，StorageRef = {bucket, objectKey}。

### 6.2 选择与切换

- 全局 `attachment.store.type = local|minio` 配置；也可按用户覆盖。
- 附件服务只依赖 `AttachmentStorage` 接口，上传/下载/预览统一。
- MigrationService 支持历史附件在 local↔minio 间迁移（不中断下载）。

### 6.3 访问安全

- 下载/预览走鉴权接口，或 MinIO 预签名 URL（带 TTL 与桶策略），不直接暴露路径。
- 上传进行类型白名单与大小限制。

## 9. 关键流程设计

### 9.1 发送邮件

```
前端 POST /api/messages(内容+附件引用)
 -> MailService 校验用户/配额
 -> 写草稿态到 OST(可选)
 -> 投递到 MQ send.queue
 -> SenderWorker 通过 SMTP(TLS/STARTTLS/OAuth2) 发送
 -> 成功: 写"已发送"到 OST; 失败: 重试/失败队列 + 审计
```

### 9.2 接收 + 规则 + 推送

```
SyncWorker(IMAP IDLE)
 -> 新邮件 -> 写入 OST 并更新 messages 摘要
 -> 触发 rule engine(若命中: 移动到folder/标记已读/打星等)
 -> 发布 mail.events.{userId}
 -> PushHub 经 WS 推送 -> 前端刷新列表/未读数
```

## 10. 技术选型与配置（概要）

| 层次 | 选型 | 备注 |
| --- | --- | --- |
| 前端 | Vue 3 + TS + Vite + Pinia + Vue Router + Element Plus | PWA: vite-plugin-pwa + Workbox |

| 部署 | Maven/Gradle、Docker、Nginx(WS 代理)、可选 K8s | |

### 主要配置项（示例）

```yaml

    type: minio            # local | minio
    local-root: /data/attachments
    minio:
      endpoint: http://minio:9000

  push: idle               # idle | polling
  poll-interval-ms: 120000
  idle-max-idle-ms: 1740000
push:
  heartbeat-ms: 30000
  reconnect-base-ms: 1000
security:
  jwt-secret-env: JWT_SECRET
  key-env: MASTER_KEY
  ost-encrypt: false
transfer:
  pst-max-import-mb: 100
```

## 14. 风险与对策（概要设计层面）

| 风险 | 对策 |
| --- | --- |
| PST 库兼容性不足 | POC-1 前置，必要时自研序列化器 |
| IMAP IDLE 长连接运维成本 | 心跳/重连/降级，连接数监控与配额 |
| OST 文件损坏 | 版本号+校验和+周期备份+重建 |
| 高并发 OST 写竞争 | 用户级文件锁 + 异步写队列 |
| WebSocket 连接数 | 横向扩展 PushHub，按用户路由 |
| 双存储迁移中断 | 迁移期间读写切换策略，版本化 StorageRef |
