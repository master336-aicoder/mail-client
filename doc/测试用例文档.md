## 3. 认证模块（Auth）

前置：后端与前端已启动。

### TC-AUTH-001 登录 · 成功（P0）
- **按钮/控件**：登录页【登录】按钮
- 前置：已注册 `tester1`
- 步骤：输入正确用户名密码 → 点击【登 录】
- 预期：请求 `POST /api/auth/login`，返回 `{accessToken,expiresIn,user}`；跳转 `/mail`；localStorage 存 `access_token` 与 `user`；顶栏显示用户名

### TC-AUTH-002 登录 · 密码错误（P0）
- **按钮**：登录页【登 录】
- 步骤：输入错误密码点击登录
- 预期：接口返回 code=40101；提示“用户名或密码错误”；停留登录页；不写 token

### TC-AUTH-003 登录 · 空校验（P1）
- **按钮**：表单校验
- 步骤：清空用户名或密码点击登录
- 预期：表单项出现“请输入用户名/密码”，不发请求

### TC-AUTH-004 登录 · Enter 键触发（P2）
- **交互**：密码框回车
- 预期：等同点击登录

### TC-AUTH-005 注册 · 成功（P0）
- **按钮**：注册 Tab →【注 册】
- 步骤：切换到“注册”，填用户名/密码/确认密码/邮箱 →点击注册
- 预期：`POST /api/auth/register` 通过；提示“注册成功，请登录”；自动切到登录 Tab 并回填用户名

### TC-AUTH-006 注册 · 用户名已存在（P1）
- **步骤**：注册已存在用户名
- 预期：code=40002 提示“用户名已存在”

### TC-AUTH-007 注册 · 两次密码不一致（P0）
- **步骤**：确认密码与密码不同
- 预期：前端校验拦截，提示“两次密码不一致”，不发请求

### TC-AUTH-008 注册 · 密码过短（P1）
- **步骤**：密码 < 6 位
- 预期：提示“密码至少 6 位”

### TC-AUTH-009 退出登录（P0）
- **按钮**：顶栏用户菜单【退出登录】
- 步骤：登录后点击头像下拉 → 退出登录
- 预期：清空 token/user；跳转 `/login`；后续请求 401 引导登录

### TC-AUTH-010 会话有效性 · 未登录访问受保护页（P0）
- **步骤**：登出后直接访问 `/mail`
- 预期：路由守卫重定向到登录页

### TC-AUTH-011 Token 失效处理（P1）
- **步骤**：篡改/过期 token 后调用 `/api/accounts`
- 预期：返回 401；前端清除 token 并跳转登录

### TC-AUTH-012 /api/auth/me（P1）
- **接口**：`GET /api/auth/me`（带 Bearer）
- 预期：返回当前用户 id；前端 fetchMe 回填 user 并持久化

### TC-AUTH-013 越权 · 普通用户访问 /api/admin（P0）
- **步骤**：tester 带 token 请求 `/api/admin/users`
- 预期：403 被拒

### TC-AUTH-014 越权 · 管理员访问后台（P1）
- **步骤**：admin 登录 → 侧栏出现【系统管理】；请求 `/api/admin/users` 成功
- 预期：200，返回用户列表

> 除前端按钮外，补充后端关键契约与异常码验证。码约定：0 成功 / 40002 用户名已存在 / 40100 未登录 / 40101 登录失败 / 40300 越权 / 50000 系统错误 / 50001 发送失败。

### TC-API-001 `POST /api/auth/register`（P0）
- 入参 `{username,password,email}`；成功 0；重复用户名 40002；缺参数 400

### TC-API-002 `POST /api/auth/login`（P0）
- 正确→`{accessToken,expiresIn,user}`；错误→40101

### TC-API-003 `GET /api/auth/me`（P1）
- 带 Bearer→uid；无 token→40100

### TC-API-004 `POST /api/accounts/auto-detect`（P1）

### TC-API-005 `GET /api/accounts`（P1）
- 返回当前用户账户列表

### TC-API-006 `POST /api/accounts`（P1）
- 保存账户与加密凭据；返回实体含 id/active

### TC-API-007 `DELETE /api/accounts/{id}`（P0）
- 非本人→40300；本人→删除成功 0

### TC-API-008 `GET /api/folders`（P1）
- 返回文件夹树（含 total/unread）

### TC-API-009 `POST /api/folders`（P0）
- 创建自定义文件夹；同用户下可多级（parentId）

### TC-API-010 `PUT /api/folders/{id}`（P1）

### TC-API-011 `DELETE /api/folders/{id}`（P1）

### TC-API-012 `GET /api/folders/{folderId}/messages`（P0）

### TC-API-013 `GET /api/messages/{id}`（P1）
- 返回详情（正文/附件/ostRef）；越权 40300

### TC-API-014 `POST /api/messages`（P0）

### TC-API-015 `POST /api/messages/draft`（P1）

### TC-API-016 `PUT /api/messages/{id}/flags`（P1）
- 更新 read/starred/important 位图

### TC-API-017 `DELETE /api/messages/{id}`（P1）
- 软删除 deleted=true；列表隐藏

### TC-API-018 `POST /api/attachments`（P0）
- multipart 上传；按 storage-mode 落本地/MinIO；写 attachment_meta

### TC-API-019 `GET /api/attachments/{id}/content`（P1）
- 按 storage_type 路由读取；正确 Content-Disposition

### TC-API-020 `GET/POST/PUT/DELETE /api/rules/**`（P1）
- 规则 CRUD + toggle + reorder；字段 JSON conditions/actions

### TC-API-021 `POST /api/transfer/export`（P1）
- 入参 `{accountId, folderIds, format}`；`format` ∈ {`zip`,`mbox`}；非法值（如 `ost`/`pst`）→40000“不支持的导出格式，仅支持 zip 或 mbox”；合法→返回任务对象（id/status/progress），异步产出 .zip（每封 .eml）或 .mbox

### TC-API-022 `GET /api/transfer/{taskId}`（P1）
- 查询导出任务状态

### TC-API-022a `POST /api/transfer/import/upload`（P1）
- multipart 上传 .pst/.mbox 到临时目录；返回 uploadToken/文件名/大小；仅接受白名单扩展名，其它 40000

### TC-API-022b `POST /api/transfer/import`（P1）
- 依据上传句柄启动导入任务；PST 走 java-libpst 只读解析、MBOX 按 `From ` 分隔切分；重复 Message-ID 去重；返回任务对象

### TC-API-023 `POST /api/sync`（P1）
- 手动同步单账户；越权 40300

### TC-API-024 `GET /api/health`（P0）
- 返回 `{status:"UP",db:"UP"}`；白名单免鉴权

### TC-API-025 WS `/api/ws?token=`（P0）
- 有效 token 可连；无效 token 被拒(POLICY_VIOLATION)

### TC-API-026 WS 事件·MAIL_NEW（P0）
- 新邮件入库后向该用户推送 `{type,data}`

### TC-API-027 WS 事件·RULE_TRIGGERED（P1）
- 规则命中推送

### TC-API-028 Security · CORS（P1）
- `Origin: http://localhost:5173` 放行；其它源拒绝

### TC-API-029 Security · 405/404 兜底（P2）
- 未知路径返回统一 JSON 封装错误

### TC-API-030 统一返回结构（P0）
- 所有 /api 响应均为 `{code,message,data}`；成功 code=0

### TC-API-031 `GET /api/admin/system-status`（P1）
- 仅 ROLE_ADMIN；返回 `{sampledAt,cpu,memory,disks[],jvm,network}`；USER 角色→403

### TC-API-032 `GET /api/admin/system-alert-config`（P1）
- 返回单例配置（id=1）：`enabled/cpuThresholdPct/memThresholdPct/diskThresholdPct/checkIntervalMin/cooldownMin/last*AlertAt`

### TC-API-033 `PUT /api/admin/system-alert-config`（P1）
- 阈值字段必须在 1~100（间隔 1~1440、冷却 0~1440），越界→40000 中文提示；非数字→40000；保存后返回最新配置

### TC-API-034 `POST /api/admin/system-alert-check`（P1）
- 立即强制巡检（force=true）：绕过 checkIntervalMin，但**遵守 cooldownMin**；返回 `{fired:[...],suppressed:[...]}`；触发项向全体 ADMIN 扇出 SYSTEM_ALERT 站内信

### TC-API-035 `POST /api/admin/system-alert-reset-cooldown`（P1）
- 将 last*AlertAt 置空并保存；用于测试后复位冷却；返回重置后的配置

### TC-API-036 `PUT /api/settings`（theme 持久化，P1）
- `{theme:"dark"}` → 写 `user_settings.theme`；另一会话 `GET /api/settings` 返回同值（跨设备同步来源）

### TC-API-037 `GET /api/tasks/runtime`（P1）
- 仅 ROLE_ADMIN；返回 `{schedulingEnabled, watchdog:{active,intervalSec,lastSweepAt,totalRecovered}}`；`schedulingEnabled` 反映启动参数 `mail.app.scheduling-enabled`；USER→403

### TC-API-038 `POST /api/tasks/watchdog-sweep`（P1）
- 仅 ROLE_ADMIN；立即触发一次孤儿执行巡检（非 @Scheduled，独立线程），返回 `{recovered:N}`；把进程内无存活 future 且 `created_at` 超过 2 分钟宽限的 `RUNNING` 记录回收为 `FAILED`；幂等，二次调用 `recovered=0`

## 12. 端到端业务场景（E2E）

### TC-E2E-001 注册 → 绑定邮箱 → 收信 → 阅读（P0）
1. 注册 tester_e2e；
2. 账户管理用自动探测+授权码绑定一个 IMAP 邮箱；
3. 外部向该邮箱发一封信并触发同步；
4. 进入收件箱，见新邮件且未读加粗；
5. 点击打开 → 标记已读，正文渲染。

### TC-E2E-002 发送 → 对方收取（P0）
1. 绑定含发件能力的账号；
2. 写邮件发给 tester2；
3. 发送成功；tester2 邮箱收到并能阅读。

### TC-E2E-003 规则自动归类（P1）
1. 新建规则：正文包含“会议”→ 移入已删除/星标；
2. 发一封含“会议”的邮件触发同步；
3. 断言：命中动作、RULE_TRIGGERED 推送、邮件状态更新。

### TC-E2E-004 离线访问（P1）
1. 安装 PWA 并打开一次；
2. 断网；
3. 重新打开 → 从缓存加载主界面与已缓存邮件列表。

### TC-E2E-005 实时推送联动（P1）
1. 保持工作台在线；
2. 另一账号发邮件；
3. 顶栏“实时推送已连接”，新邮件即时标红/列表自动刷新（无需手动）。

### TC-E2E-006 导出 → 标准客户端读取（P1）
1. 选择收件箱邮件，导出格式选 **MBOX 归档 (.mbox)** 或 **EML 打包 (.zip)**；
2. 下载产物；MBOX 用 Thunderbird/import-import 读取，EML 逐封可被 Outlook/邮件客户端打开；
3. 断言：MBOX 每封以 `From ` 行分隔、`>From ` 已转义；zip 内含对应数量 `.eml`；内容/主题/收件人完整。
> 说明：本系统不生成二进制 PST/OST（java-libpst 只读，OST 为账户绑定的在线同步文件），故改为诚实的标准格式导出。
