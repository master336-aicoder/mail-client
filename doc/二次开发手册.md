## 1. 项目概述

云邮 Mail 是一个多用户 Web 邮箱客户端，用户通过浏览器绑定自己的邮箱账户（IMAP/POP3/SMTP），在 Web 端完成收件、发件、文件夹管理、筛选规则、PST 导出等操作。

**核心能力**：
- 多协议邮箱绑定（IMAP4 / POP3 / SMTP，SSL / STARTTLS / NONE）
- 服务端工作存储（OST）+ PST 导出供 Outlook 读取
- 实时推送（WebSocket）+ 定时同步
- 筛选规则引擎
- PWA 离线访问
- 管理后台（用户管理、公告发布）

**架构模式**：单进程同源托管 — 前端 SPA 打包后嵌入 Spring Boot jar 的 `classpath:/static`，一个 Java 进程同时提供页面、REST API、WebSocket。

## 3. 开发环境搭建

### 3.1 前置条件

| 组件 | 版本 | 安装路径（参考） |
|------|------|----------------|
| JDK | 21 | `D:\Java\jdk-21` |
| Maven | 3.6.3+ | `D:\apache-maven-3.6.3` |
| Node.js | 22+ | 系统 PATH |
| MySQL | 8.x | localhost:3306 |
| Redis | 3.2+ | localhost:6379 |

### 3.2 初始化数据库

```sql
CREATE DATABASE IF NOT EXISTS mail_client
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;
```

表结构由 Flyway 在应用首次启动时自动创建。

### 3.3 启动后端

```bash
cd backend
export JAVA_HOME="D:\Java\jdk-21"

# 方式一：Maven 直接运行（推荐开发使用）
mvn spring-boot:run -Dspring-boot.run.profiles=dev

# 方式二：先打包再运行
mvn clean package -DskipTests
java -jar target/mail-client-backend-1.0.0.jar --spring.profiles.active=dev
```

> **dev profile** 放行仓库内置默认密钥并允许内网邮件服务器连接，仅限开发使用。

后端启动后监听 `http://localhost:8080`。

### 3.4 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端开发服务器监听 `http://localhost:5173`，Vite 自动将 `/api` 请求代理到 `localhost:8080`（含 WebSocket）。

### 3.5 一键启动（使用脚本）

```powershell
# 编译打包 + 启动后端
powershell -ExecutionPolicy Bypass -File deploy\build.ps1 -Dev

# 或启动已打包的 jar
powershell -ExecutionPolicy Bypass -File deploy\build.ps1 -Run
```

## 5. 后端架构

### 5.1 分层结构

每个业务模块遵循标准分层：

```
account/
├── AccountController.java       # REST 接口层
├── AccountService.java          # 业务逻辑层
├── domain/
│   ├── MailAccount.java         # JPA 实体
│   └── MailAccountRepository.java  # Spring Data Repository
└── dto/
    ├── AccountRequest.java      # 请求 DTO
    └── ProbeResult.java         # 响应 DTO
```

### 5.2 核心模块说明

| 模块 | 包路径 | 职责 |
|------|--------|------|
| **auth** | `com.mail.auth` | 登录/注册/登出、JWT 签发与解析、Cookie 管理、CSRF 校验、登录限流 |
| **account** | `com.mail.account` | 邮箱账户 CRUD、自动探测服务器配置、凭据加解密、用户设置 |
| **protocol** | `com.mail.protocol` | 邮件协议抽象层：`MailClient` 接口 + IMAP/POP3 实现、TLS 配置、内容解析 |
| **mail** | `com.mail.mail` | 邮件列表/详情/发送/草稿、SMTP 传输、附件管理、内联附件 |
| **folder** | `com.mail.folder` | 文件夹树 CRUD、未读数统计 |
| **rule** | `com.mail.rule` | 筛选规则 CRUD、规则引擎执行 |
| **sync** | `com.mail.sync` | 收信同步编排：拉取 → 入库 → 规则匹配 → 推送 |
| **task** | `com.mail.task` | 异步任务框架：任务定义、执行记录、产物附件、保存策略 |
| **push** | `com.mail.push` | WebSocket 推送服务：MAIL_NEW 等事件 |
| **storage** | `com.mail.storage` | 附件存储抽象：`AttachmentStorage` 接口 + 本地/MinIO 实现 |
| **notification** | `com.mail.notification` | 用户通知 + 管理员公告 |
| **common** | `com.mail.common` | 响应信封 `ApiResponse`、业务异常 `BizException`、加密服务、全局异常处理 |
| **config** | `com.mail.config` | Spring Security、WebSocket、SPA 转发、MinIO 配置绑定 |

### 5.3 请求处理链路

```
HTTP 请求
  → JwtAuthFilter（解析 Cookie/Header 中的 JWT，CSRF 校验）
  → Spring Security 鉴权
  → Controller（参数校验 @Valid）
  → Service（业务逻辑）
  → Repository（数据访问）
  → ApiResponse 包装响应
  → GlobalExceptionHandler 统一异常处理
```

### 5.4 异步任务框架

任务框架采用三层模型：

```
Task（任务定义）
  ├── 周期配置（间隔/定点/CRON）
  ├── 保存策略（保留天数/范围）
  └── TaskRun（执行记录）
        ├── 状态/进度/错误信息
        └── TaskAttachment（产物附件）
```

扩展新任务类型：
1. 实现 `TaskHandler` 接口
2. 在 `TaskHandlerRegistry` 注册
3. 前端任务页自动展示

### 5.5 附件存储

`AttachmentStorage` 接口支持两种实现：

| 实现 | 条件 | 存储位置 |
|------|------|---------|
| `LocalFileStorage` | `storage-mode=local` | `./data/attachments` |
| `MinioStorage` | `storage-mode=minio` | MinIO bucket |

`StorageRouter` 根据配置的 `storage-mode` 路由到对应实现。

### 6.3 HTTP 层

`http.ts` 封装了 Axios 实例：

- `baseURL: '/api'` — 所有 API 请求自动加前缀
- `withCredentials: true` — 随请求携带 HttpOnly Cookie
- **请求拦截器**：非安全方法（POST/PUT/DELETE）自动附加 `X-CSRF-Token` 头（从 `csrf_token` Cookie 读取）
- **响应拦截器**：
  - 解包 `ApiResponse` 信封，直接返回 `data` 字段
  - 401 → 清除会话 + 跳转登录页 + 提示"登录状态已失效"
  - 其他错误 → 中文友好提示

### 6.4 状态管理

使用 Pinia 管理全局状态：

| Store | 职责 |
|-------|------|
| `auth` | 用户信息、登录态、角色 |
| `mail` | 当前文件夹、选中邮件、未读数 |
| `notification` | 通知列表、未读数 |

## 7. API 规范

### 7.1 统一响应信封

所有 API 返回统一 JSON 格式：

```json
{
  "code": 0,
  "message": "ok",
  "data": { ... }
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | `0` 成功，非 `0` 为业务错误码 |
| `message` | string | 可读描述（中文） |
| `data` | any | 业务数据（错误时为 `null`） |

### 7.2 错误码约定

| 范围 | 说明 |
|------|------|
| `0` | 成功 |
| `40000-40099` | 通用参数错误 |
| `40100` | 未认证/会话失效 |
| `40300-40399` | 权限不足 / CSRF 失败 |
| `40400` | 资源不存在 |
| `50000-50099` | 服务器内部错误 |

业务异常通过 `throw new BizException(code, message)` 抛出，由 `GlobalExceptionHandler` 统一捕获并包装为 `ApiResponse`。

### 7.3 REST 端点总览

| 模块 | 路径前缀 | 说明 |
|------|---------|------|
| 认证 | `/api/auth` | 登录/注册/登出/改密/当前用户 |
| 账户 | `/api/accounts` | 邮箱账户 CRUD、自动探测、测试连接 |
| 设置 | `/api/settings` | 用户全局设置 |
| 文件夹 | `/api/folders` | 文件夹树 CRUD |
| 邮件 | `/api` (根) | 邮件列表/详情/发送/草稿/标记/删除/批量移动 |
| 附件 | `/api/attachments` | 附件上传/下载 |
| 内联附件 | `/api/inline` | 正文内联图片 |
| 规则 | `/api/rules` | 筛选规则 CRUD |
| 同步 | `/api/sync` | 手动触发收信 |
| 任务 | `/api/tasks` | 任务定义/执行记录/批量操作 |
| 任务附件 | `/api/task-attachments` | 任务产物下载 |
| 通知 | `/api/notifications` | 用户通知 |
| 传输 | `/api/transfer` | PST 导出 |
| 管理 | `/api/admin` | 用户管理（ADMIN 角色） |
| 公告 | `/api/admin/announcements` | 公告管理（ADMIN 角色） |
| 健康 | `/api/health` | 健康检查（公开） |

### 7.4 认证方式

- **Cookie 模式**（默认）：`access_token` HttpOnly Cookie 承载 JWT
- **CSRF 防护**：非安全方法需回传 `X-CSRF-Token` 头（值与 `csrf_token` Cookie 一致）
- **WebSocket**：通过 URL 查询参数 `?token=xxx` 传递 JWT

### 7.5 新增 API 步骤

1. 在对应模块创建 Controller：
   ```java
   @RestController
   @RequestMapping("/api/xxx")
   public class XxxController {
       @GetMapping
       public ApiResponse<List<XxxDto>> list() { ... }
   }
   ```
2. 在 `api/index.ts` 添加前端 API 函数
3. 如需新权限，在 `SecurityConfig` 配置路径规则

**命名规范**：`V{N}__{描述}.sql`

```
V1__init.sql

...
V13__task_run_policy.sql
```

新增迁移：创建 `V14__your_feature.sql`，应用启动时 Flyway 自动执行。

### 8.2 JPA 配置

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: validate   # 生产环境只校验不修改
    open-in-view: false    # 关闭 OSIV，避免懒加载陷阱
```

## 9. 安全机制

### 9.1 认证流程

```
登录 → AuthService 验证密码 → 签发 JWT → 写入 access_token Cookie (HttpOnly)
                                         → 写入 csrf_token Cookie
                                         → 响应体返回 user + expiresIn

后续请求 → JwtAuthFilter 解析 Cookie → 设置 SecurityContext
         → 非安全方法 → 校验 X-CSRF-Token 头 == csrf_token Cookie
```

### 9.2 密钥管理

| 密钥 | 用途 | 存储位置 | 轮换 |
|------|------|---------|------|
| `JWT_SECRET` | JWT HS256 签名 | 服务环境变量 | 可以（所有会话失效） |
| `MASTER_KEY` | 邮箱凭据 AES-256-GCM | 服务环境变量 | **不可**（凭据无法解密） |

### 9.3 安全防护清单

| 威胁 | 防护措施 |
|------|---------|
| XSS | 后端 JSoup 白名单 + 前端 DOMPurify |
| CSRF | HttpOnly Cookie + 双重提交 |
| SSRF | `HostGuard` 校验邮件主机，禁止内网/回环 |
| 路径穿越 | 附件文件名净化 + 路径包含校验 |
| 暴力破解 | Redis 滑动窗口限流 |
| 越权 | `CurrentUser` 线程变量 + 归属校验 |
| 默认密钥 | `SecretsValidator` 启动 fail-fast |

### 9.4 新增受保护接口

1. 默认所有 `/api/**` 需认证（`SecurityConfig` 配置）
2. 公开端点加入 `permitAll()` 列表
3. 管理员端点使用 `.hasRole("ADMIN")` 或 `@PreAuthorize("hasRole('ADMIN')")`

## 12. 编码约定

### 12.1 后端

- **包结构**：按业务模块分包，每个模块含 Controller/Service/domain/dto
- **命名**：类名 PascalCase，方法/变量 camelCase，常量 UPPER_SNAKE_CASE
- **异常**：业务异常统一用 `BizException`，消息使用中文
- **响应**：统一用 `ApiResponse` 包装
- **DTO**：请求用 `XxxRequest`，响应用 `XxxDto` / `XxxItem`
- **实体**：JPA 实体放 `domain` 子包，Repository 同包
- **配置**：使用 `@ConfigurationProperties` 绑定，前缀 `mail.app.*`

### 12.2 前端

- **组件**：页面级放 `views/`，可复用放 `components/`
- **命名**：文件名 PascalCase（Vue 组件）/ camelCase（TS）
- **API**：统一在 `api/index.ts` 按域分组导出
- **状态**：全局状态用 Pinia store，局部状态用 `ref`/`reactive`
- **样式**：使用 `styles/tokens.css` 中的设计令牌
- **类型**：尽量使用 TypeScript 类型标注

### 12.3 数据库

- **表名**：snake_case 复数（`users`, `messages`）
- **列名**：snake_case
- **主键**：`id BIGINT AUTO_INCREMENT`
- **时间**：`created_at` / `updated_at`，由 JPA `@CreatedDate` / `@LastModifiedDate` 自动填充
- **外键**：`xxx_id` 命名（`user_id`, `account_id`）
- **迁移**：每个变更一个 Flyway 脚本，`V{N}__描述.sql`

## 13. 常见问题

### 13.1 启动被拒绝：检测到不安全的默认密钥

**原因**：生产模式（非 dev profile）下使用了仓库内置默认密钥。

**解决**：通过环境变量注入真实密钥：
```bash
export JWT_SECRET="your-256bit-secret..."
export MASTER_KEY="your-256bit-secret..."
```

### 13.2 前端代理 404

**原因**：后端未启动或端口不是 8080。

**解决**：确认后端运行在 `localhost:8080`，或修改 `vite.config.ts` 中的 proxy target。

### 13.3 WebSocket 连接失败

**原因**：`publicOrigin` 与浏览器地址不一致。

**解决**：确保 `settings.json` 中 `publicOrigin` 与实际访问地址完全一致（scheme + host + port）。

### 13.4 邮箱凭据解密失败

**原因**：`MASTER_KEY` 被更换。

**解决**：回滚到旧 `MASTER_KEY`。该密钥不可轮换。

### 13.5 Flyway 迁移冲突

**原因**：多人开发时创建了相同版本号的迁移脚本。

**解决**：协调版本号，确保每个脚本版本号唯一。已执行的脚本不可修改。

### 13.6 登录报 CSRF 错误

**原因**：反向代理未透传 Cookie，或 HTTPS 部署未设置 `authCookieSecure=true`。

**解决**：检查代理配置；HTTPS 部署时设置 `authCookieSecure=true` 并更新配置。
