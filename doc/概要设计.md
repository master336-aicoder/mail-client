## 1. 设计概述

### 1.1 设计目标

在需求分析基础上，将系统分解为**职责清晰、边界明确、可独立演进**的模块，明确各模块的接口契约、数据流、关键算法与部署形态，为详细设计与编码提供蓝图。

### 1.2 设计约束

- 首期以「模块化单体（Modular Monolith）」落地：一个 Boot 应用内含多个有序模块，模块间通过接口与受限的包依赖通信，禁止跨模块直接访问实现。
- 自带邮箱由本系统服务器处理；Webmail 也可**绑定外部 IMAP/SMTP 账户**（代理模式），两套引擎共用存储抽象与业务服务。
- 邮件原始数据落 EML 文件，元数据落 MySQL/PostgreSQL，会话与限流用 Redis。
- 协议引擎基于 Netty 非阻塞 IO，与 Spring Web 容器共享主进程。

### 1.3 设计权衡与说明

| 决策点 | 选择 | 理由 |
| --- | --- | --- |
| 模块化单体 vs 微服务 | 模块化单体起步，预留抽取 | 降低首期部署与事务复杂度；负载上升时 mail-protocol、web-api 可水平多实例 |
| 自研协议引擎 vs 集成现成 | 自研（Netty + 状态机） | 可控、可插拔、贴合 Spring 生态；规避重型 MTA 的强耦合 |
| IMAP 存储 | 目录 = Mailbox，EML 文件 = 消息，UID 与文件一一对应 | 与 RFC 同步语义天然一致，便于备份迁移 |
| 全文检索 | Lucene 内嵌起步，接口抽象，后续换 ES | 首期无额外组件，留有演进空间 |

### 2.1 分层职责

| 层 | 职责 | 依赖方向 |
| --- | --- | --- |
| 接入层（协议引擎/Web Controller） | 会话、请求解析、参数校验 | → 业务域 |
| 业务域（Mail Core / Admin Service） | 领域逻辑、事务、规则 | → 存储/基础设施 |
| 存储抽象层 | MailboxStore、MetadataRepository、IndexService | → 具体实现 |
| 基础设施 | DB、Redis、文件系统、队列 | 无上层依赖 |

### 2.2 模块依赖规则（Maven 层面）

- `mail-common` 是最底层，可被所有模块依赖。
- 协议模块（smtp/imap/pop3）与 `mail-web-api` 都仅依赖 `mail-core` 与 `mail-storage`，彼此不互相依赖。
- `mail-storage` 依赖 `mail-core`（使用其模型）与 `mail-common`。
- `mail-admin` 复用 `mail-web-api` 的安全与用户体系。
- 禁止：业务模块反向依赖协议模块、Controller 直接操作 Repository。

## 3. 模块设计

### 3.1 `mail-common`（公共）

- **内容**：统一异常、统一响应体（`R<T>`）、工具类（Base64、字符串、ID 生成）、配置封装、通用安全（JWT、密码加密）、日志（logback）、常量与枚举。
- **对外契约**：`R<T>` 响应、`BizException`、`IdGenerator`、`SecurityUtils`。

### 3.2 `mail-core`（邮件领域核心）

| 构件 | 职责 |
| --- | --- |
| `MailParser` | MIME 解析为内存模型 `MailMessage`（头、正文、部件、附件）；支持流式读取大附件 |
| `MailEncoder` | 将模型序列化为 EML 原文（写盘前调用） |
| `MailMessage`(模型) | Header 集合、Body 结构树、Attachment 列表；不可变 + Builder |
| `DeliveryQueue` | 持久化投递队列，管理重试、延迟、退信生成 |
| `MailIndexService`(接口) | 索引/检索统一入口；Lucene 实现，预留 ES |
| `AddressResolver` | 解析收件人，判定本域/外域，别名与转发展开 |

**关键接口**

```java
public interface MailboxService {
    long append(UUID folderId, MailMessage msg, List<String> flags);   // 返回 uid
    void expunge(UUID folderId, Set<Long> uids);
    MailMessage fetch(UUID folderId, long uid);
    void setFlags(UUID folderId, long uid, Map<String, Boolean> flags);
    List<MailMessage> list(UUID folderId, int page, int size, Sort sort);
}
```

### 3.3 `mail-storage`（存储抽象层）

- `MailboxStore`：`put(uid, InputStream)` / `get(uid)` / `delete(uid)`，实现 `FsMailboxStore`（文件系统）与 `S3MailboxStore`（对象存储）。
- `MailboxLayout`：路径规则 `{root}/{domain}/{user}/{mailboxName}/{uid}.eml`，集中管理命名与 UIDVALIDITY。
- 元数据通过 `mail-core` 内的 Repository 访问 JPA 实体。

### 3.4 `mail-protocol-smtp`（SMTP 引擎）

- **Netty 管线**：`FramingDecoder` → `CommandParser` → `SmtpHandler`（会话状态机）→ `ResponseEncoder`。
- **会话状态机**：`CONNECTED → GREETED → MAIL → RCPT → DATA → ACCEPTED → QUIT`；驱动超时。
- **认证**：`Authenticator` 接口，内置 LOGIN/PLAIN，预留 CRAM-MD5/OAUTH2。
- **线程模型**：Netty EventLoop 处理 IO，投递与 EML 落盘提交到业务线程池，避免阻塞 IO 线程。

### 3.5 `mail-protocol-imap`（IMAP 引擎）

- **会话状态机**：`NOT_AUTHENTICATED → AUTHENTICATED → SELECTED`（RFC 3501）。
- **命令分发**：命令经 `ImapCommandDispatcher` 路由到对应处理器（Fetch、Store、Search…）。
- **UID 同步**：基于存储层返回的 uid 与 `UIDNEXT`/`UIDVALIDITY` 维护。
- **IDLE**：由 Redis Pub/Sub 或内存订阅新邮件通知触发响应。

### 3.6 `mail-protocol-pop3`（POP3 引擎）

- 会话简单状态机 + 下载行式输出；支持 STLS。

### 3.7 `mail-web-api`（Web 前端服务）

- **Controller**：REST 端点（见 §6），统一鉴权（Spring Security + JWT）。
- **Service**：邮件列表、详情、移动、搜索、草稿、发送、通讯录、多账户代理。
- **多账户代理**：对绑定外部账户，通过内嵌 IMAP/SMTP 客户端代理读写，统一映射为内部邮件模型。

### 3.8 `mail-admin`（系统管理）

- 域、用户、配额、别名/转发、日志审计、监控、备份的 REST 服务。
- 管理端用户角色 `ROLE_ADMIN` 与普通用户 `ROLE_USER` 权限分离。

## 4. 关键技术方案

### 4.1 协议引擎（Netty + 状态机）

- 每个协议实现一个 `ChannelInboundHandler`，持有类型安全的状态机。
- 统一连接/读写超时（默认 SMTP 10min、IMAP 30min 空闲）。
- 通过 `ChannelGroup` 统一管理连接，便于峰值与下线控制。

### 4.2 MIME 解析与编码

- 解析采用流式：先读头部，再按 body 分部流式读取；防止超长头/超大正文耗尽内存。
- 数据模型用父子结构 `MimePart`，支持 `multipart/mixed|alternative|related`。
- 编码解码封装在 `mail-common`，支持 `Base64`、`Quoted-Printable`、7bit/8bit、UTF-8 等常见字符集（通过 `mail-common` 字符集映射）。

### 4.3 投递队列（持久化 + 重试）

- 表 `mail_queue` 记录状态机：`PENDING → DELIVERING → SUCCEED | RETRY | FAILED`。
- 后台调度器每 N 秒扫描 `next_attempt_at <= now` 的任务，指数退避重试（如 1/2/4/8/30/60 分钟，上限约 5 次）。
- 本域投递：直接调用 `MailboxService.append` 并更新元数据；外域：走 SMTP 客户端出站连接（内置出站 SMTP 客户端 `SmtpClient`）。
- 重试超限 → 生成 NDR 退信。

### 4.4 全文搜索（Lucene 起步）

- 索引文档：subject、body(text)、from/to/cc、附件名、日期、uid、folders。
- 一用户一索引目录，提交时刷新 `IndexWriter`，检索走 `QueryParser`。
- `IndexService` 为接口，后续替换 ES 时改实现。

### 4.5 缓存与限流（Redis）

- 会话：Spring Session Redis 或自维护 JWT + 黑名单。
- 登录失败计数（`incr`+`expire`）+ SMTP 发送计数按 `(ip/user)` 限流（滑动窗口 Lua 脚本）。
- 灰名单：`SET key (from,to) EX 300 NX`，首次放行后的重试间隔记忆。
- 新邮件通知：Redis Pub/Sub `channel:mail:{user}` 供 IMAP IDLE 与 Web long-poll 消费。

### 4.6 并发与一致性

- 单实例内用 `ConcurrentHashMap` 维护 `(folderId,uid)` 锁，避免同文件夹并发 append 冲突。
- 元数据更新走事务；EML 文件采用「先写临时文件再原子 rename」保证落盘完整。
- 多实例时 UID 分配依赖数据库行锁或取 max(uid)+1 并配合唯一约束；首期单实例为主。

## 5. 数据模型设计

### 5.1 ER 总览

```text
sys_domain 1 ─── * sys_user
sys_user   1 ─── * mail_folder            (本域用户的文件夹)
mail_folder  1 ── * mail_message
mail_message 1 ── * mail_attachment
sys_user   1 ─── * mail_contact
mail_contact 1 ── * (多) contact_group    (绑定关系表)
sys_user   1 ─── * mail_account           (外部绑定账户)
*(全局) mail_queue ; admin_audit_log ; push_sync_cursor
```

### 5.2 核心表结构（DDL 要点）

```sql
-- 域
CREATE TABLE sys_domain (
  id           BIGINT PRIMARY KEY,
  name         VARCHAR(255) NOT NULL UNIQUE,
  alias        VARCHAR(255),
  enabled      TINYINT(1) DEFAULT 1,
  max_quota    BIGINT DEFAULT 0,       -- 字节
  created_at   DATETIME
);

-- 用户
CREATE TABLE sys_user (
  id            BIGINT PRIMARY KEY,
  domain_id     BIGINT NOT NULL,
  username      VARCHAR(128) NOT NULL,
  display_name  VARCHAR(128),
  password_hash VARCHAR(255) NOT NULL,
  status        VARCHAR(16) DEFAULT 'ACTIVE',  -- ACTIVE/DISABLED
  quota_bytes   BIGINT DEFAULT 0,
  used_bytes    BIGINT DEFAULT 0,
  email         VARCHAR(255) GENERATED ALWAYS AS (CONCAT(username,'@',(SELECT name FROM sys_domain WHERE id=domain_id))) VIRTUAL,
  UNIQUE KEY uk_user_domain (domain_id, username)
);

-- 文件夹
CREATE TABLE mail_folder (
  id           BIGINT PRIMARY KEY,
  user_id      BIGINT NOT NULL,
  name         VARCHAR(255) NOT NULL,
  path         VARCHAR(512),          -- 如 "INBOX"/"INBOX/Projects"
  parent_id    BIGINT,
  uid_validity BIGINT NOT NULL,
  uidnext      BIGINT DEFAULT 1,
  created_at   DATETIME
);

-- 邮件元数据
CREATE TABLE mail_message (
  id              BIGINT PRIMARY KEY,
  folder_id       BIGINT NOT NULL,
  uid             BIGINT NOT NULL,
  message_id      VARCHAR(500),
  subject         VARCHAR(1000),
  from_addr       VARCHAR(500),
  from_name       VARCHAR(500),
  to_addrs        TEXT,
  cc_addrs        TEXT,
  date_sent       DATETIME,
  size_bytes      BIGINT,
  flags           VARCHAR(64) DEFAULT '',   -- 逗号分隔，如 "Seen,Answered"
  has_attachments TINYINT(1) DEFAULT 0,
  preview         VARCHAR(2000),
  eml_path        VARCHAR(1500),
  thread_id       BIGINT,
  UNIQUE KEY uk_folder_uid (folder_id, uid)
);

-- 附件
CREATE TABLE mail_attachment (
  id           BIGINT PRIMARY KEY,
  message_id   BIGINT NOT NULL,
  file_name    VARCHAR(500),
  mime_type    VARCHAR(255),
  size_bytes   BIGINT,
  storage_path VARCHAR(1500),
  content_id   VARCHAR(255),
  sequence     INT,                     -- 部件顺序
  FOREIGN KEY (message_id) REFERENCES mail_message(id)
);

-- 联系人
CREATE TABLE mail_contact (
  id        BIGINT PRIMARY KEY,
  user_id   BIGINT NOT NULL,
  name      VARCHAR(128),
  email     VARCHAR(500) NOT NULL,
  phone     VARCHAR(64),
  company   VARCHAR(255),
  remark    VARCHAR(1000),
  avatar    VARCHAR(1500)
);
CREATE TABLE contact_group (id BIGINT PK, user_id BIGINT, name VARCHAR(128));
CREATE TABLE contact_group_map (contact_id BIGINT, group_id BIGINT, PRIMARY KEY(contact_id, group_id));

-- 外部账户绑定
CREATE TABLE mail_account (
  id            BIGINT PRIMARY KEY,
  user_id       BIGINT NOT NULL,
  email         VARCHAR(500) NOT NULL,
  protocol_type VARCHAR(16),       -- SMTP/IMAP
  host          VARCHAR(255),
  port          INT,
  username      VARCHAR(255),
  enc_password  TEXT,              -- AES-GCM 加密
  is_default    TINYINT(1) DEFAULT 0
);

-- 投递队列
CREATE TABLE mail_queue (
  id              BIGINT PK,
  sender          VARCHAR(500),
  recipients      TEXT,
  status          VARCHAR(16),     -- PENDING/DELIVERING/RETRY/SUCCEED/FAILED
  retry_count     INT DEFAULT 0,
  next_attempt_at DATETIME,
  raw_path        VARCHAR(1500),   -- EML 缓存文件
  created_at      DATETIME
);

-- 审计日志
CREATE TABLE admin_audit_log (
  id BIGINT PK, admin_id BIGINT, action VARCHAR(64),
  target VARCHAR(255), detail TEXT, ip VARCHAR(64), created_at DATETIME
);
```

### 5.3 索引建议

- `mail_message(folder_id, uid)` 唯一索引为主查询路径；`(message_id)` 索引用于会话聚合。
- `mail_queue(status, next_attempt_at)` 扫描投递；`sys_user(domain_id, username)` 唯一。

## 7. 核心流程设计

### 7.1 本域收信流程（外部 → 本系统）

```text
外部MTA --SMTP--> SmtpHandler(认证/规则校验)
   └─ DATA 完成 → MailParser 流式解析 → MailEncoder/落 EML 临时文件
       → 遍历收件人，AddressResolver 判定本域
       → 每组(receiver) 调用 MailboxService.append 到 INBOX/别名解析后文件夹
       → 事务内更新 mail_message 元数据 + mail_queue(SUCCEED)
       → 发布 Redis 通知(channel:mail:{user})
       → 返回 250 2.0.0 OK
```

### 7.2 外域投递流程

```text
Webmail/提交 SMTP → 入队 mail_queue(PENDING)
  └─ 调度器扫描 → DNS/MX 解析 → SmtpClient 出站发送
      ├─ 成功 → SUCCEED
      └─ 失败 → RETRY，next_attempt_at = now + 退避
                └─ 超限 → 生成 NDR 退信回发件人
```

### 7.3 Webmail 发信流程

```text
前端 /api/mail/send
  → Controller 鉴权 → MailService.compose（组装 MailMessage）
  → 本域？直接 append + 入队(标记本域已投递) / 外域？整体入队
  → 同时写入「已发送」文件夹元数据 → 返回 messageId
  → 异步：调度器完成实际出站投递
```

### 7.4 邮件移动/删除流程

```text
/api/mail/messages/{id}/move {toFolderId, mode}
  → 事务：更新 mail_message.folder_id（复制时新增记录并复制 EML 引用/复制文件）
  → flags 更新 \Deleted → 待 expunge
  → 垃圾箱删除为逻辑删除，配置保留天数后清理
```

### 7.5 IMAP 同步（新邮件推送）

```text
MailboxService.append → Redis Pub/Sub 通知
  → IMAP SELECT 且 IDLE 中 → 返回 * 1 EXISTS /新 uid 事件
  → Web long-poll：订阅 channel，推送到前端更新未读
```

### 7.6 登录流程

```text
POST /api/auth/login(账号,口令)
  → 校验 BCrypt → 发行 JWT(access + refresh)
  → Redis 记录会话，登录失败计数+1，超阈值锁定
  → 审计日志记录
```

## 8. 安全设计

### 8.1 分层安全

| 层 | 措施 |
| --- | --- |
| 传输 | 协议 STARTTLS/SMTPS/IMAPS/POP3S；Web 全部 HTTPS；证书可配置（内置自签/外部） |
| 认证 | BCrypt 密码；协议 SASL；JWT（HS256，短期+refresh） |
| 授权 | `ROLE_ADMIN` / `ROLE_USER` 方法级 `@PreAuthorize` |
| 会话 | Token 过期、黑名单撤销、登录失败限流锁定 |
| 数据 | 外部账户口令 AES-GCM 加密；主密钥环境变量注入；日志脱敏邮箱/口令 |
| 防注入与 XSS | 参数校验 Bean Validation；HTML 正文渲染前用白名单消毒（如 jsoup）消毒 |
| 反滥用 | SPF 校验（预留）、DKIM 签名（预留）、发件域白名单、SMTP 限流与灰名单 |

### 8.2 密钥与敏感信息

- 主密钥：`MAIL_MASTER_KEY` 环境变量 / KMS；用于口令字段加密与 EML 可选透明加密。
- 不做：明文口令存储、日志打印 token/口令。

## 10. 部署设计

### 10.1 单机（开发/小型）

- Docker Compose：`mail-app` + `mysql`/`postgres` + `redis`；
- `mail-app` 暴露 8080（Web）、25/465、143/993、110/995；
- 前端由 `mail-app` 托管静态资源或 Nginx 反代 `/api` 与 Web 协议端口。

### 10.2 分层（生产）

```text
Nginx(LB/TLS终结)
 ├── mail-app-1 / mail-app-2   (Web API, 可水平)
 ├── mail-protocol 实例 (SMTP/IMAP/POP3)   —— 与 Web 分离时独立部署
 └── Redis / MySQL / 共享存储(FS or S3) / 可选 ES
```

- 协议实例与 Web 实例分离：同共享存储 + DB，实现负载均衡与故障切换。
- 证书由运维注入；端口按安全组开放。

### 10.3 编排

- 提供 `docker-compose.yml` 与 Kubernetes 的 Deployment/Service 清单（后续阶段）。
- 健康检查：`GET /actuator/health`；启动自检确保 DB/存储可连。

## 11. 运维与监控设计

### 11.1 日志

- 结构化 JSON 日志（logback + `json-encoder`），包含 `traceId`。
