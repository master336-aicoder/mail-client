## 4. 修复细节与验证

### 4.1 F-01 · 401 toast 去重（`frontend/src/api/http.ts`）

新增模块级时间戳与函数：

```ts
// 同一批并行 401 只弹一次「登录失效」提示，避免登录后旧会话残留请求触发连串 toast。
let authExpiredToastAt = 0
function notifyAuthExpired() {
  const now = Date.now()
  if (now - authExpiredToastAt < 3000) return
  authExpiredToastAt = now
  ElMessage.error('登录状态已失效，请重新登录')
}
```

401 分支调用点由 `ElMessage.error(...)` 改为 `notifyAuthExpired()`；跳转与清 localStorage 行为保持不变。

### 4.2 F-04 · AdminView 权限失败态（`frontend/src/views/AdminView.vue`）

- 新增 `denied` / `deniedReason` 响应式状态
- `load()` 改用 `http.get('/admin/users', { silentError: true })`：403 显示「当前账号没有管理员权限」；401 显示「登录状态已失效」；其他错误显示 `err.message`；三种情况都置 `denied.value=true`、`users.value=[]`
- 模板顶部条件渲染 `<el-alert v-if="denied" ... />`；「用户列表」和「发布站内信」两张卡改为 `v-if="!denied"` 隐藏
- `onMounted` 串行 `await load()` 再触发 `loadHistory()`，`loadHistory` 在 `denied.value=true` 时短路返回；同时把 `adminApi.announcements` 也换成 `http.get(..., { silentError: true })` 避免叠加 toast

## 8. 需求逐项执行结果

### 8.1 导出格式选择（诚实替代 OST）— 通过

- **变更**：`TransferService.startExport` 新增 `format ∈ {zip, mbox}` 校验；`PstExportTaskHandler` 拆出 `exportZip()` / `exportMbox()`。
- **正向（zip）**：对沙盒账户导出生成 `.zip`，解压得 **10 个 `.eml`** 文件，每封可被邮件客户端打开。
- **正向（mbox）**：导出生成 `.mbox`，`grep -c '^From '` = **10**，`>From ` 转义正确，日期行符合 `From <addr> <ctime>` 格式。
- **反向（非法格式）**：`format="ost"` → HTTP 400 体 `{"code":40000,"message":"不支持的导出格式，仅支持 zip 或 mbox"}`。
- **诚实说明**：`/transfer` 页面顶部 el-alert 明确「二进制 PST/OST 无法由本系统生成（java-libpst 只读，OST 账户绑定）」。

### 8.2 系统监控 + 预警扇出真实触发 — 通过

- `GET /api/admin/system-status`：返回 CPU/内存/磁盘/JVM/网络采样，Windows 下阈值着色正确。
- `PUT /api/admin/system-alert-config` 越界校验：`cpuThresholdPct=150` → 40000「CPU 阈值需在 1 ~ 100 之间」；非数字 → 40000。
- **扇出（第一轮）**：阈值下调至必然触发 → `POST /system-alert-check` 返回 `fired` 含 CPU/内存/磁盘 3 项；DB 中 3 位 ADMIN × 3 指标 = **9 条 SYSTEM_ALERT 站内信**；`last*AlertAt` 已写入。
- **冷却抑制（第二轮）**：立即再次 `POST /system-alert-check` → `fired=[]`、`suppressed` 含 3 项（遵守 cooldownMin，验证冷却去重）。
- **重置冷却**：`POST /system-alert-reset-cooldown` → last*AlertAt 置空；再次巡检 `fired` 恢复 3 项，再扇出 **9 条**（两轮累计 18 条站内信）。
- **禁用**：`enabled=false` 时 `runCheck` 直接返回，不采样、不扇出（TC-ADM-010）。

### 8.3 主题跨设备/跨浏览器同步 — 通过

# 追加：v1.3 后台任务守护进程 + 调度状态展示

> 版本：v1.3 · 日期：2026-10-13 · 关联用例：`doc/测试用例文档.md` §10 (TC-ADM-017/018) / §11 (TC-API-037/038)

## 12. 需求

为后台任务建立守护进程，防止执行异常（`RUNNING` 记录因线程丢失而永久「进行中」并阻塞再次调度），并把启动参数 `--mail.app.scheduling-enabled` 的开关状态展示在后台任务界面。

## 13. 实现

- **`TaskWatchdog`（新增，`com.mail.task`）**：`@Component`，用独立 `java.util.concurrent.ScheduledExecutorService`（单守护线程 `task-watchdog`）在 `ApplicationReadyEvent` 后 `scheduleWithFixedDelay` 每 60 秒巡检一次；**刻意不用 `@Scheduled`**，因此 `--mail.app.scheduling-enabled=false` 时守护照常运行。暴露 `isActive/getLastSweepAt/getTotalRecovered` 与手动 `sweepNow()`，`@PreDestroy` 关闭线程池。
- **`TaskService.sweepOrphanRuns()`（新增）**：遍历库中 `RUNNING/PENDING` 记录，跳过 `created_at` 晚于 `ORPHAN_GRACE`（2 分钟）的新执行；对进程内 `running` map 无存活 future 者，用 `findStatus` 复核后回收为 `FAILED`，回填 error「守护进程检测到执行线程已丢失，本轮执行中断，可点击「立即执行」重试」+ `finished_at`，`notifyFailure` 并 `log.warn`。与只处理进程重启的 `reconcileAfterRestart` 互补，无需 schema 迁移。
- **`AppProperties.schedulingEnabled`（映射 `mail.app.scheduling-enabled`，默认 true）+ `GET /api/tasks/runtime`**：返回 `{schedulingEnabled, watchdog:{active,intervalSec,lastSweepAt,totalRecovered}}`；**`POST /api/tasks/watchdog-sweep`** 立即巡检返回 `{recovered}`。
- **前端 `TasksView.vue`**：头部横幅两枚标签——【定时调度】（关闭时附注启动参数提示）+【守护进程】运行中/巡检间隔/上次时间/累计回收，右侧【立即巡检】按钮。

## 14. 端到端验证（真实执行）

重启后用一次性 ADMIN 用户 `wdtest01`（验证后已清理）实测：

1. `GET /api/tasks/runtime` → `200 {schedulingEnabled:false, watchdog:{active:true, intervalSec:60, ...}}`：**调度已关（启动参数 `--mail.app.scheduling-enabled=false`），守护进程仍 active**，与启动日志「后台任务守护进程已启动：每 60 秒巡检一次孤儿执行」一致。
2. INSERT 孤儿 `task_runs(status='RUNNING', created_at=NOW()-INTERVAL 5 MINUTE)`（进程内无 future）→ `POST /watchdog-sweep` → `{recovered:1}`，记录转 `FAILED`、`finished_at` 回填、error 文案正确。
3. 二次 `POST /watchdog-sweep` → `{recovered:0}`（幂等）；`runtime.totalRecovered` 由 0→1。

构建链全部通过：`mvn compile` RC=0、`vue-tsc` RC=0、`npm build` RC=0（32 precache）、`mvn package` RC=0，SPA 注入 jar 同进程启动 health UP。
