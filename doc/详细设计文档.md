# Web 版邮箱客户端 —— 技术详细设计文档

> 版本：v1.0
> 关联：需求分析文档 v1.1、概要设计文档 v1.0
> 技术栈：Spring Boot 3（后端）+ Vue 3 + TypeScript + PWA（前端）

---

## 1. 范围

本文档在概要设计基础上，将每个模块细化到：数据库物理表与 DDL、后端类层次与关键实现、REST/WS 接口的完整入参与出参、核心流程时序、配置项、PST 导出与实时推送的关键技术细节，供开发编码直接使用。

### 1.1 已确认技术边界

| 项 | 结论 |
| --- | --- |
| 协议 | 仅 IMAP4 / POP3 / SMTP（无 Exchange） |
| Outlook 兼容 | 仅单向**导出为 PST** 供 Outlook 打开读取 |
| 推送 | 实时：IMAP IDLE + WebSocket，降级轮询 |
| 附件 | 本地文件系统 + MinIO 双存储，抽象可切换 |
| 离线 | PWA（vite-plugin-pwa + Workbox） |

## 3. 数据库详细设计

### 3.1 物理表 DDL

```sql
-- 用户表
CREATE TABLE users (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  username      VARCHAR(64)  NOT NULL UNIQUE,
  password_hash VARCHAR(100) NOT NULL,          -- BCrypt/Argon2
  email         VARCHAR(255),
  mfa_enabled   TINYINT      NOT NULL DEFAULT 0,
  storage_quota BIGINT       NOT NULL DEFAULT 1073741824, -- 字节，默认1GB
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- 邮箱账户（凭据密文引用）
CREATE TABLE mail_accounts (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id        BIGINT       NOT NULL,
  email          VARCHAR(255) NOT NULL,
  display_name   VARCHAR(128),
  protocol       VARCHAR(10)  NOT NULL,          -- IMAP | POP3
  host           VARCHAR(255) NOT NULL,
  port           INT          NOT NULL,
  encryption     VARCHAR(16)  NOT NULL DEFAULT 'TLS', -- NONE|SSL|STARTTLS
  auth_type      VARCHAR(16)  NOT NULL DEFAULT 'PASSWORD', -- PASSWORD|OAUTH2
  username       VARCHAR(255) NOT NULL,          -- 登录账号
  credential_ref VARCHAR(64)  NOT NULL,          -- 指向 credentials 表
  smtp_host      VARCHAR(255),
  smtp_port      INT,
  smtp_encryption VARCHAR(16) DEFAULT 'STARTTLS',
  is_active      TINYINT      NOT NULL DEFAULT 1,
  created_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_user (user_id),
  CONSTRAINT fk_acct_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB;

-- 凭据密文（对称加密）
CREATE TABLE credentials (
  ref            VARCHAR(64)  PRIMARY KEY,       -- 随机 ref
  user_id        BIGINT       NOT NULL,
  encrypted_algo VARCHAR(16)  NOT NULL DEFAULT 'AES-256-GCM',
  iv             VARBINARY(16) NOT NULL,
  ciphertext     VARBINARY(512) NOT NULL,
  tag            VARBINARY(16) NOT NULL,
  created_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- 文件夹（与 OST 映射）
CREATE TABLE folders (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id     BIGINT       NOT NULL,
  account_id  BIGINT,
  parent_id   BIGINT,
  name        VARCHAR(128) NOT NULL,
  folder_type VARCHAR(20)  DEFAULT 'USER',       -- ROOT|INBOX|SENT|DRAFT|TRASH|JUNK|USER
  ost_path    VARCHAR(255),
  sort_order  INT          DEFAULT 0,
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user_parent (user_id, parent_id),
  CONSTRAINT fk_folder_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB;

-- 邮件摘要（用于列表/搜索；正文在 OST）
CREATE TABLE messages (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id     BIGINT       NOT NULL,
  account_id  BIGINT       NOT NULL,
  folder_id   BIGINT       NOT NULL,
  imap_uid    BIGINT,                            -- IMAP UID / POP3 顺序号
  message_id  VARCHAR(255),                      -- Message-ID 头
  subject     VARCHAR(512),
  from_addr   VARCHAR(255),
  from_name   VARCHAR(128),
  to_addrs    TEXT,
  cc_addrs    TEXT,
  received_at DATETIME,
  size        BIGINT,
  flags       INT          DEFAULT 0,            -- 位图: READ|STARRED|IMPORTANT|HAS_ATTACH
  body_preview VARCHAR(500),
  ost_ref     VARCHAR(255),                      -- OST 中正文对象引用
  deleted     TINYINT      NOT NULL DEFAULT 0,
  created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user_folder (user_id, folder_id, received_at),
  KEY idx_user_flag (user_id, flags),
  FULLTEXT KEY ft_subject(subject) ,
  CONSTRAINT fk_msg_folder FOREIGN KEY (folder_id) REFERENCES folders(id)
) ENGINE=InnoDB;

-- 附件元数据（内容存本地/MinIO）
CREATE TABLE attachment_meta (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id        BIGINT       NOT NULL,
  message_id     BIGINT       NOT NULL,
  name           VARCHAR(255) NOT NULL,
  mime           VARCHAR(128),
  size           BIGINT,
  store_type     VARCHAR(10)  NOT NULL,          -- LOCAL | MINIO
  local_path     VARCHAR(512),                   -- 本地存储相对路径
  bucket         VARCHAR(64),                    -- MinIO 桶
  object_key     VARCHAR(512),                   -- MinIO 对象键
  created_at     DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_msg (message_id),
  CONSTRAINT fk_att_msg FOREIGN KEY (message_id) REFERENCES messages(id)
) ENGINE=InnoDB;

-- 规则
CREATE TABLE rules (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id    BIGINT       NOT NULL,
  name       VARCHAR(128) NOT NULL,
  priority   INT          NOT NULL DEFAULT 0,
  enabled    TINYINT      NOT NULL DEFAULT 1,
  conditions JSON,                               -- [{field,op,value}]
  actions    JSON,                               -- [{action,param}]
  created_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
  KEY idx_user (user_id),
  CONSTRAINT fk_rule_user FOREIGN KEY (user_id) REFERENCES users(id)
) ENGINE=InnoDB;

-- 同步日志/游标
CREATE TABLE sync_jobs (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id    BIGINT NOT NULL,
  account_id BIGINT NOT NULL,
  folder_id  BIGINT,
  type       VARCHAR(16) NOT NULL,               -- IMAP_IDLE | POLL | SEND
  status     VARCHAR(16) NOT NULL,               -- RUNNING|OK|FAILED|DEGRADED
  last_uid   BIGINT,
  message    VARCHAR(500),
  started_at DATETIME,
  finished_at DATETIME,
  KEY idx_account (account_id)
) ENGINE=InnoDB;

-- 审计日志
CREATE TABLE audit_logs (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id    BIGINT,
  actor      VARCHAR(64),
  action     VARCHAR(64) NOT NULL,               -- LOGIN|SEND|RECV|RULE|IMPORT|EXPORT|ADMIN_*
  target     VARCHAR(255),
  detail     TEXT,
  ip         VARCHAR(64),
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_user_time (user_id, created_at)
) ENGINE=InnoDB;
```

```json
// 请求
{ "username": "alice", "password": "***" }
// 响应 data
{ "accessToken": "...", "refreshToken": "...", "expiresIn": 3600, "user": { "id":1, "username":"alice" } }
```

### 5.2 账户

**POST /api/accounts/auto-detect**
```json
// 请求
{ "email": "alice@gmail.com" }
// 响应 data(探测到的推荐配置列表)
[{ "protocol":"IMAP","host":"imap.gmail.com","port":993,"encryption":"SSL",
   "smtpHost":"smtp.gmail.com","smtpPort":587,"smtpEncryption":"STARTTLS" }]
```

**POST /api/accounts**
```json
// 请求
{ "email":"a@b.com","displayName":"A","protocol":"IMAP","host":"imap.gmail.com",
  "port":993,"encryption":"SSL","authType":"OAUTH2","username":"a@b.com",
  "secret":"应用密码或授权码","smtpHost":"smtp.gmail.com","smtpPort":587 }
```
> 后端：校验连接成功后，secret 加密入 credentials，返回 accountId。

### 5.3 邮件

**GET /api/folders/{folderId}/messages?page=1&size=50&flag=unread&q=**
```
响应 data: { total, list:[ {id,folderId,subject,from,name,date,flags,hasAttach,preview,size} ] }
```

**GET /api/messages/{id}**
```
data: { id, subject, from, to[], cc[], date, flags, bodyHtml(已清洗), bodyText, attachments[{id,name,mime,size}], ostRef }
```

**POST /api/messages**（发送）
```json

  "subject":"Hi","bodyHtml":"<p>...</p>","attachments":[{"metaId":10}] }
```

**PUT /api/messages/{id}/flags**  `{ "read":true, "starred":false, "important":true }`

## 6. 附件双存储详细设计

### 6.1 接口

```java
public interface AttachmentStorage {
  StorageRef store(String userId, InputStream in, String name, String mime, long size);
  InputStream open(StorageRef ref);
  void delete(StorageRef ref);
  String presignedUrl(StorageRef ref, Duration ttl);
  boolean exists(StorageRef ref);
}
```

### 6.2 本地实现（LocalFileStorage）

- 路径规则：`attachments/{userId}/{yyyy}/{mm}/{uuid}/{filename}`
- StorageRef.localPath = 相对路径（不落绝对路径）
- presignedUrl 返回带签名的短期下载接口 URL

### 6.3 MinIO 实现（MinioStorage）

- bucket：`mail-attachments`（按需按 userId 前缀）
- objectKey：`{userId}/{uuid}/{safeName}`
- presignedUrl：MinIO 预签名 GET（5 分钟），下载前校验权限

### 6.4 切换与迁移

- 配置 `storage.attachment.type=local|minio`，AttachmentService 注入默认实现。
- StorageRef 自带 storeType，读取时按其类型路由到对应实现（据此可迁移混存）。
- MigrationService：从 A 读出→写入 B→更新 attachment_meta 的 storeType/path 与 objectKey；原子两步提交。

## 7. 实时推送详细实现

### 7.1 IMAP IDLE worker

```
SyncWorker(accountId):
  loop:
    确保连接 -> SELECT folder
    if server 支持 IDLE:
       向 server 发 IDLE
       收到 EXISTS 新邮件 -> break -> 增量 sync
       IDLE 超时(N分钟) -> 发 DONE -> 重进 IDLE
       例外/断连 -> 重连; 连续失败 > N -> 降级 POLL
    else: 定时 POLL(每 poll-interval)
  增量 sync:
    取 lastUid -> 拉 uid>\lastUid 的新邮件 -> 写 OST + messages 摘要
    update lastUid -> 发布 mail.events.{userId}
```

### 7.2 WebSocket 推送链路

```
PushService.publish(userId, event)
  -> 持久化/写审计(可选)
  -> MQ topic mail.events.{userId}
Wall 订阅 -> PushHub 路由到该用户在线 WS session -> 前端收到 event
```

### 7.3 心跳与重连

- 服务端每 30s 心跳校验连接；空闲过长 ping 前端。
- 客户端断线：指数退避重连（1s,2s,4s...，上限 60s）。
- 连接恢复后：前端拉一次增量（补漏）。

## 8. PST 导出/导入详细

### 8.1 导出 POC 优先（风险最高）

- POC-1 先验证选定的 Java PST Writer 是否满足：打开、正文、附件、文件夹 在 Outlook 2013~365 全部可读。
- 若社区库不足，则实现最小自研 PST 序列化器（仅需 Level-2 基本结构：文件夹 + 消息 + 附件 + 头部）。

### 8.2 导出流程（异步任务）

```
1. TransferService.createExport(userId,folderId) -> 任务入队
2. Worker: 查 DB 摘要列表 + 读 OST 正文对象
3. 组装内存对象模型(store/folders/messages)
4. 附件从本地/MinIO 拉取放入 .pst attachment
5. PstWriter 生成到临时文件 -> 完成后提供下载地址(带过期)
6. 记录 audit EXPORT
```

### 8.3 导入流程（异步）

```
1. POST /api/import/pst 上传 -> 存临时 -> 任务入队
2. PstImporter 解析(文件夹/消息/附件) -> 附件落库+内容入存储
3. 写入用户 OST + messages 摘要 -> 完成通知(WS) -> audit IMPORT
限: 单文件 <= transfer.pst-max-import-mb(默认100MB)
```

## 9. 关键流程时序（详细）

### 9.1 接收+规则+推送

```
SyncWorker            OST        rule          MQ              PushHub       前端
    |--SELECT收件箱--->|          |             |                |             |
    |--IDLE(等新邮件)-+-           |             |                |             |
    |--有新邮件        |           |             |                |             |
    |--增量拉取-------->|写消息     |             |                |             |
    |--发布新邮件事件---+--------->|             |                |             |
    |                  |          |--评估规则---"                |             |
    |                  |          |--执行动作->写OST             |             |
    |                  |          |             |--publish------->|             |
    |                  |          |             |                |--WS推送------> 用户
```

### 9.2 附件上传（组成草稿并发）

```
前端: 附件 -> POST /attachments(预上传) -> 返回 metaId
前端: 发送邮件 bodyHtml + 附件 metaId[] -> POST /messages
后端: SMTP 发送 -> 写已发送到 OST -> 发布事件 -> 返回 messageId
```

## 11. 安全实现要点

| 项 | 实现 |
| --- | --- |
| JWT | HS256，claim: sub=userId, role；短期 access + refresh；WS 握手校验 |
| 凭据 | AES-256-GCM，密钥主控 MASTER_KEY；库内仅 ciphertext+iv+tag |
| 内容 | HTML 用白名单清洗（去 script/事件属性外链），图片懒加载+代理 |
| 附件 | 上传类型白名单+大小限制；下载鉴权；MinIO 桶私有+预签名 |
| 审计 | login/send/recv/rule/import/export/admin 均落库 |
| 越权 | 所有 Service 以 userId 过滤数据，防水平越权 |
