## 1. 系统架构概览

```
浏览器 ──http(s)──▶ Spring Boot 后端 :8080
                      ├─ /              前端 SPA（history 回退 index.html）
                      ├─ /assets/**     前端静态资源（classpath:/static）
                      ├─ /api/**        REST 接口（JSON 信封 {code,message,data}）
                      ├─ /api/ws        WebSocket 实时推送
                      └─ /api/health    健康检查端点
外部依赖：
  ├─ MySQL 8       主数据存储（Flyway 自动建表/迁移）
  ├─ Redis 3.2+    登录限流 / 令牌黑名单
  └─ MinIO（可选）  附件对象存储（默认本地文件）
```

**技术栈**：
- 后端：Java 21 + Spring Boot 3.3.4 + Spring Security + JPA/Hibernate + Flyway
- 前端：Vue 3 + TypeScript + Vite + Element Plus + PWA
- 认证：JWT HS256 + HttpOnly Cookie + CSRF 双重提交
- 加密：BCrypt（密码）+ AES-256-GCM（邮箱凭据）

## 2. 部署拓扑

### 单进程同源托管（默认/推荐）

前端 `dist` 在打包时嵌入 jar 的 `classpath:/static`，由后端一个进程同时提供页面、API、WebSocket。

```
                    ┌──────────────────────────┐
 浏览器 :5173(dev)  │   mail-client.jar        │
 ─────────────────▶ │   Spring Boot :8080      │
 或生产直接 :8080    │   ├─ SPA 静态资源         │
                    │   ├─ /api/*  REST API     │
                    │   └─ /api/ws  WebSocket   │
                    └──────────┬───────────────┘
                               │
              ┌────────────────┼────────────────┐
              ▼                ▼                ▼
          MySQL :3306     Redis :6379     MinIO :9000(可选)
```

### 反向代理拓扑（生产推荐）

```
 浏览器 ──HTTPS──▶ Nginx/IIS :443 ──HTTP──▶ localhost:8080
```

反向代理负责 TLS 终止、WebSocket 升级头转发、静态资源缓存。

## 4. 安装部署

### 4.1 打包制品（在构建机执行）

```powershell
powershell -ExecutionPolicy Bypass -File deploy\package.ps1 -Version 1.0.0
```

产出 `dist-release\mail-client-1.0.0.zip`，包含：
- `app\mail-client-backend-1.0.0.jar`（已内嵌前端）
- `config\` 配置模板
- `scripts\` 部署脚本
- `VERSION.json` 版本清单（含 jar SHA256）

### 4.2 首次安装（在服务器执行）

```powershell
# 解压制品包
Expand-Archive mail-client-1.0.0.zip -DestinationPath C:\deploy\mail-client-1.0.0

cd C:\deploy\mail-client-1.0.0\scripts

# 第一步：生成 settings.json（含随机密钥）
powershell -ExecutionPolicy Bypass -File .\install.ps1

# 编辑 config\settings.json，核对数据库/Redis/端口等配置
# 第二步：正式安装
powershell -ExecutionPolicy Bypass -File .\install.ps1 -Confirm
```

安装脚本依次执行：
1. 校验管理员权限、定位 java/nssm/jar
2. 创建安装目录结构（app/config/logs/backups/data）
3. 拷贝 jar，渲染 application-prod.yml
4. 创建 MySQL 数据库（表由 Flyway 首启自动建）
5. 注册 NSSM 服务（密钥通过服务环境变量注入，不写入 yml）
6. 启动服务并轮询健康检查

### 4.3 快速开发启动

```powershell
# 一键编译打包
powershell -ExecutionPolicy Bypass -File deploy\build.ps1

# 以 dev profile 直接运行（跳过打包）
powershell -ExecutionPolicy Bypass -File deploy\build.ps1 -Dev

# 启动已打包的 jar
powershell -ExecutionPolicy Bypass -File deploy\build.ps1 -Run
```

## 6. 配置说明

### 6.1 配置文件层次

| 文件 | 位置 | 说明 |
|------|------|------|
| `application.yml` | jar 内 / classpath | 基础配置（端口、JPA、Flyway、Jackson） |
| `application-dev.yml` | jar 内 / classpath | 开发 profile（放行默认密钥） |
| `application-prod.yml` | `<安装目录>\config\` | 生产配置（由模板渲染生成） |
| `settings.json` | `scripts\config\` 或 `<安装目录>\config\` | 部署设置（含密钥，**勿提交版本库**） |

### 6.2 settings.json 关键字段

| 字段 | 说明 | 默认值 |
|------|------|--------|
| `serviceName` | Windows 服务名 | `mail-client` |
| `installDir` | 安装目录 | `C:\mail-client` |
| `serverPort` | 服务端口 | `8080` |
| `publicOrigin` | 对外访问根地址（CORS + WS 来源校验） | 必须与实际浏览器地址一致 |
| `authCookieSecure` | HTTPS 部署置 true | `false` |
| `allowPrivateHost` | SSRF 防护，连内网邮件服务器时置 true | `false` |
| `storageMode` | 附件存储：`local` 或 `minio` | `local` |
| `jwtSecret` | JWT 签名密钥（自动生成，**不可轮换**） | 随机 64 位 hex |
| `masterKey` | 邮箱凭据加密密钥（自动生成，**升级时切勿更换**） | 随机 64 位 hex |
| `db.*` | MySQL 连接信息 | localhost:3306 |
| `redis.*` | Redis 连接信息 | localhost:6379 |

### 6.3 环境变量覆盖

生产环境密钥通过 NSSM 服务环境变量注入（不写入 yml）：

```
JWT_SECRET=<64位hex>
MASTER_KEY=<64位hex>
```

开发环境可通过命令行参数覆盖：

```bash
java -jar app.jar --mail.app.jwt-secret=xxx --mail.app.master-key=xxx
```

### 6.4 安全开关

| 配置项 | 生产值 | 说明 |
|--------|--------|------|
| `mail.app.allow-insecure-defaults` | `false` | 禁止使用默认密钥，启动 fail-fast |
| `mail.app.allow-private-host` | `false` | SSRF 防护，禁止连接内网邮件主机 |
| `mail.app.auth-cookie-secure` | `true`（HTTPS） | Cookie 加 Secure 属性 |

## 9. 备份与恢复

### 9.1 自动备份脚本

```powershell
# 完整备份（数据库 + 附件 + 配置）
powershell -ExecutionPolicy Bypass -File deploy\backup.ps1

# 仅备份数据库
powershell -ExecutionPolicy Bypass -File deploy\backup.ps1 -SkipAttachments

# 保留最近 14 份
powershell -ExecutionPolicy Bypass -File deploy\backup.ps1 -Retention 14
```

备份内容：
- `mail_client.sql` — mysqldump 全库备份（--single-transaction）
- `attachments.zip` — 附件目录打包
- `application-prod.yml` — 配置快照
- `settings.json` — 部署设置快照

备份位置：`<安装目录>\backups\backup-<时间戳>\`

默认保留最近 7 份，超出自动清理。

### 9.2 手动备份

```powershell
# 数据库
mysqldump -h localhost -P 3306 -u root -proot --single-transaction --routines --triggers mail_client > mail_client-backup.sql

# 附件
Compress-Archive -Path C:\mail-client\data\attachments -DestinationPath attachments-backup.zip
```

### 9.3 恢复

```powershell
# 恢复数据库
mysql -h localhost -P 3306 -u root -proot mail_client < backup-dir\mail_client.sql

# 恢复附件
Expand-Archive -Path backup-dir\attachments.zip -DestinationPath C:\mail-client\data\

# 恢复配置
Copy-Item backup-dir\application-prod.yml C:\mail-client\config\
# 重启服务
powershell -ExecutionPolicy Bypass -File deploy\service.ps1 restart
```

> 恢复数据库前请先停止服务，恢复完成后再启动。

## 10. 版本升级

### 10.1 升级流程

```powershell
# 1. 在构建机打包新版本
powershell -ExecutionPolicy Bypass -File deploy\package.ps1 -Version 1.0.1

# 2. 将 zip 上传到服务器并解压
Expand-Archive mail-client-1.0.1.zip -DestinationPath C:\deploy\mail-client-1.0.1

# 3. 执行升级
cd C:\deploy\mail-client-1.0.1\scripts
powershell -ExecutionPolicy Bypass -File .\upgrade.ps1 -ReleaseDir C:\deploy\mail-client-1.0.1
```

升级脚本自动执行：
1. **备份**：mysqldump 数据库 + 快照旧 jar/配置
2. **换件**：停服务 → 替换 jar → 重渲染配置
3. **迁移**：启动服务，Flyway 自动执行增量数据库迁移
4. **健康检查**：轮询 `/api/health`，失败则自动回滚

### 10.2 注意事项

- **masterKey 不可更换**：更换后已存储的邮箱凭据无法解密
- **jwtSecret 不可更换**：更换后所有用户会话失效
- **Flyway 迁移不可逆**：升级前务必确认数据库备份
- 升级脚本默认执行完整备份，可用 `-SkipBackup` 跳过


## 13. 安全加固

### 13.1 密钥管理

| 密钥 | 用途 | 生成方式 | 可否轮换 |
|------|------|---------|---------|
| `JWT_SECRET` | JWT 签名（HS256） | install.ps1 自动生成 | 可以（所有用户需重新登录） |
| `MASTER_KEY` | 邮箱凭据 AES-256-GCM 加密 | install.ps1 自动生成 | **不可**（否则凭据无法解密） |

### 13.2 安全特性清单

- **认证**：JWT HS256 + HttpOnly Cookie + SameSite=Lax
- **CSRF**：`csrf_token` Cookie + `X-CSRF-Token` 头双重提交
- **密码**：BCrypt 哈希，注册/改密要求 ≥ 8 位
- **邮箱凭据**：AES-256-GCM 加密落库
- **SSRF 防护**：`allow-private-host=false` 时拦截内网/回环邮件主机
- **XSS 防护**：后端 JSoup 白名单清洗 + 前端 DOMPurify 净化渲染
- **路径穿越**：附件文件名净化 + 路径包含校验
- **登录限流**：Redis 滑动窗口，防暴力破解
- **CORS**：仅允许 `cors-allowed-origins` 配置的来源
- **启动校验**：生产环境使用默认密钥时 fail-fast 拒绝启动

### 13.3 安全配置检查清单

| 检查项 | 生产标准 |
|--------|---------|
| `allow-insecure-defaults` | `false` |
| `allow-private-host` | `false`（除非连接内网邮件服务器） |
| `auth-cookie-secure` | `true`（HTTPS 部署） |
| `JWT_SECRET` | 非默认值，由 install.ps1 生成 |
| `MASTER_KEY` | 非默认值，由 install.ps1 生成 |
| MySQL 密码 | 非 `root` |
| Redis 密码 | 非 `redis` |

## 14. HTTPS 与反向代理

### 14.1 Nginx 反向代理示例

```nginx
server {
    listen 443 ssl;
    server_name mail.example.com;

    ssl_certificate     /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket 支持
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400s;
    }
}
```

配置后需更新 settings.json：
- `publicOrigin` → `https://mail.example.com`
- `authCookieSecure` → `true`

然后重跑 upgrade 更新配置。

### 14.2 IIS 反向代理示例

需安装 ARR (Application Request Routing) 和 URL Rewrite 模块：

```xml
<rule name="ReverseProxy" stopProcessing="true">
    <match url="(.*)" />
    <action type="Rewrite" url="http://localhost:8080/{R:1}" />
    <serverVariables>
        <set name="HTTP_X_FORWARDED_FOR" value="{REMOTE_ADDR}" />
        <set name="HTTP_X_FORWARDED_PROTO" value="https" />
    </serverVariables>
</rule>
```

WebSocket 需在 IIS 站点中启用 WebSocket 协议。

## 15. 故障排查

### 15.1 常见问题

| 现象 | 排查步骤 |
|------|---------|
| 服务启动失败 | 查看 `logs\stderr.log`；常见原因：DB/Redis 连接失败、密钥缺失 |
| 健康检查不通过 | 确认 MySQL/Redis 服务运行中；检查 `application-prod.yml` 连接配置 |
| 页面 404/空白 | 确认打包时 dist 已拷入 jar；`jar tf app.jar \| findstr static/index.html` |
| 刷新深链 404 | 确认 `SpaWebConfig` history 回退生效 |
| 实时推送不工作 | `publicOrigin` 与浏览器地址不一致导致 WS 握手被拒 |
| 登录报 CSRF(40301) | 反向代理需透传 Cookie；HTTPS 未置 `authCookieSecure=true` |
| 邮箱凭据解密失败 | masterKey 被更换，需回滚到旧 masterKey |
| 启动被拒绝（密钥校验） | 生产环境必须注入真实 JWT_SECRET/MASTER_KEY |
| 附件上传失败 | 检查磁盘空间；MinIO 模式下检查 endpoint/bucket |
| 收信失败 | 查看任务执行记录；常见：网络超时、认证失败、证书异常 |

### 15.2 紧急恢复

```powershell
# 1. 停止服务
powershell -ExecutionPolicy Bypass -File deploy\service.ps1 stop

# 2. 查看日志定位问题
powershell -ExecutionPolicy Bypass -File deploy\logs.ps1 -Tail 100

# 3. 检查依赖服务
# MySQL
mysql -h localhost -P 3306 -u root -p -e "SELECT 1"
# Redis
redis-cli ping

# 4. 如需回滚
powershell -ExecutionPolicy Bypass -File deploy\service.ps1 start
```

### 15.3 性能排查

```powershell
# 查看 JVM 内存（需启用 JMX 或 arthas）
jps -l
jmap -heap <pid>

# 查看线程
jstack <pid> > thread-dump.txt
```

### 17.6 防火墙 / SELinux / KYSEC

- **firewalld**：`install.sh` 已自动 `firewall-cmd --permanent --zone=public --add-port=8080/tcp`。手工确认：

  ```bash
  sudo firewall-cmd --zone=public --list-all
  ```

  若通过 Nginx 反代对外仅暴露 443，可关闭 8080 外部放行，改走 `--zone=trusted` 或富规则：

  ```bash
  sudo firewall-cmd --permanent --zone=public --remove-port=8080/tcp
  sudo firewall-cmd --permanent --zone=trusted --add-source=127.0.0.1/32
  sudo firewall-cmd --permanent --zone=trusted --add-port=8080/tcp
  sudo firewall-cmd --reload
  ```

- **SELinux**：`install.sh` 检测到 Enforcing 时会给 `$INSTALL_DIR/app` 打 `bin_t`、给 `/var/log/mail-client` 打 `var_log_t`。若被拒绝，看 `/var/log/audit/audit.log`：

  ```bash
  sudo ausearch -m avc -ts recent | grep mail
  sudo yum install -y policycoreutils-python-utils   # 提供 semanage
  ```

  实在需要临时降级排障：`sudo setenforce 0`（Permissive），**上线后必须 `setenforce 1` 复原**。

- **KYSEC（麒麟安全防护）**：麒麟特有的执行控制模块，可能拒绝 systemd 拉起 `/opt/mail-client` 下的 java。install.sh 会提示，如出现 `Permission denied` 但 SELinux 已放行，多半是 KYSEC 拦截：

  ```bash
  sudo kysec-control status                          # 查看当前状态
  # 生产建议保持开启，仅将应用目录加白名单；应急可用：
  sudo kysec-control disable                        # 全关，测试完立刻 enable
  ```

```bash
# 构建机
```

`upgrade.sh` 会依次执行：
1. `mysqldump --single-transaction` 备份数据库到 `/opt/mail-client/backups/<时间戳>/mail_client-<时间戳>.sql`
2. 快照旧 jar、application-prod.yml、config/env 到同目录
3. `systemctl stop`，替换 jar（保留旧 jar 为 `.replaced`），重渲染 yml
4. 若 jar 版本号变化，`sed` 更新 `/etc/systemd/system/mail-client.service` 中的 `ExecStart` 路径，`daemon-reload`
5. `systemctl start`（Flyway 自动执行迁移），健康检查
6. 检查失败自动回滚 jar / yml / env 并重启旧版本；数据库需人工 `mysql < *.sql`

### 17.10 常见坑速查（Kylin 特有）

| 现象 | 定位 | 修复 |
|---|---|---|
| `bash: /bin/bash^M: bad interpreter` | 脚本被 Windows 编辑器保存成 CRLF | `sed -i 's/\r$//' scripts/*.sh && chmod +x scripts/*.sh` |
| 启动报 `Unable to access jarfile /opt/mail-client/app/…jar` | SELinux/KYSEC 拒绝 `mail` 用户访问 `/opt` | `sudo chmod o+rx /opt`；`sudo restorecon -RF /opt/mail-client` |
| 健康检查 `db: DOWN` | MySQL 8 未启用 `caching_sha2_password` 或主机白名单没放行 | 检查 `settings.db.user/password`；`CREATE USER … IDENTIFIED WITH mysql_native_password` 兼容 |
| `journalctl` 中 `java: command not found` | `settings.javaHome` 指到 JRE 而非 JDK，或 `bin/java` 不存在 | 修正 `javaHome` 后重跑 `install.sh --confirm` |
| WebSocket `/api/ws` 断开 | 反向代理未转发 `Upgrade/Connection` 头，或 `cors-allowed-origins` 与前端 `Origin` 不一致 | 参照第 14 节 Nginx 段；把 `settings.publicOrigin` 改为浏览器实际访问根地址 |
| `systemctl start` 卡到 `TimeoutStartSec=120` 后被 kill | Flyway 首次迁移慢（>2min），或 MySQL 连接池启动了但网络未通 | 单元中 `TimeoutStartSec` 改 300；确认 `mysql -h <host> -u mailclient -p mail_client` 能通 |
| `data/attachments` 无法写 | 属主不是 mail:mail，或 SELinux `httpd_sys_rw_content_t` 缺失 | `sudo chown -R mail:mail /opt/mail-client/data && sudo restorecon -RF /opt/mail-client/data` |
| 日志目录 `/var/log/mail-client` 不存在 | systemd `StandardOutput=append:` 不自动建目录 | install.sh 已 mkdir；若跳过：`sudo mkdir -p /var/log/mail-client && sudo chown mail:mail /var/log/mail-client` |
