## 1. 设计目标与范围

本文档在概要设计基础上，将每个模块细化到**类、方法、时序、表结构与数据结构**，为编码实现提供无歧义依据。

**细化范围**

- 后端：Maven 兄弟模块包结构、核心类职责、关键时序、字段级 DDL。
- 前端：Vue 页面路由、组件树、状态管理、UI 高保真风格。
- 协议：SMTP/IMAP/POP3 状态机与命令处理细节。

**不包含**：具体业务文案、运维手册（后续单独文档）。

## 2. 包结构与模块依赖

### 2.1 Maven 模块

```text
mail-server/  (parent pom)
 ├─ mail-common         公共：R<T>、异常、工具、安全、配置
 ├─ mail-core           领域核心：MailModel、解析、编码、投递队列、索引接口
 ├─ mail-storage        存储实现：Fs/S3 MailboxStore、元数据 Repository
 ├─ mail-protocol-smtp  SMTP 引擎
 ├─ mail-protocol-imap  IMAP 引擎
 ├─ mail-protocol-pop3  POP3 引擎
 ├─ mail-web-api        Web REST 控制器 + 业务服务
 └─ mail-admin          系统管理 REST + 管理服务
```

### 2.2 依赖方向（允许）

```text
           +-------------------------------------------------+
           | mail-web-api / mail-admin                       |
           |   (Controller → Service → Repository)           |
           +---------+--------------+-------------+----------+
                     |              |             |
                     v              v             v
            mail-protocol-{smtp,imap,pop3}  mail-storage
                     \              |             /
                      v             v            v
                             mail-core
                               ^
                               |
                           mail-common
```

- 业务模块均依赖 `mail-common` 与 `mail-core`。
- `mail-storage` 依赖 `mail-core`、`mail-common`。
- 协议模块依赖 `mail-core`、`mail-storage` 接口、`mail-common`。
- **禁止反向依赖**：`mail-core` 不依赖任何协议与 Web 模块。

## 3. 类级设计（后端核心类）

### 3.1 `mail-common`

| 类 | 职责与关键成员 |
| --- | --- |
| `R<T>` | `code/msg/data/timestamp`；静态 `ok()/error()`；错误码常量 |
| `BizException` | 业务异常 `code/msg/httpStatus` |
| `GlobalExceptionHandler` | `@RestControllerAdvice` 统一异常 → `R<T>` |
| `PageResult<T>` | `list, page, size, total` |
| `JwtUtil` | 生成/校验 access/refresh；`generate(user)/parse(token)` |
| `PasswordEncoder` | 封装 BCrypt `hash(raw)/matches(raw,hash)` |
| `AesCipher` | AES-GCM 加解密（口令加密），密钥来自主密钥派生 |
| `RedisKey` | 会话、登录失败计数、限流、灰名单、消息通道常量 |
| `JsonUtil` | Jackson 封装 |

### 3.2 `mail-core`（领域模型 + 服务接口）

**模型（不可变 POJO + Builder）**

| 类 | 字段 |
| --- | --- |
| `MailMessage` | `HeaderSet headers; BodyNode body; List<Attachment> attachments; long size; Date date; String messageId` |
| `HeaderSet` | `Map<String,List<String>>`；`subject/from/to/cc/date` 便捷方法 |
| `BodyNode` | `MimeType type; BodyNode parent; List<BodyNode> parts;` 懒加载 raw / 流式 |
| `Attachment` | `name, mimeType, size, storagePath, contentId, sequence` |
| `Flag` | 枚举 `SEEN/ANSWERED/FLAGGED/DELETED/DRAFT/RECENT` |

**核心服务接口**

```java
public interface MailParser {

public interface MailboxService {

public interface MailIndexService {

```

## 4. 核心时序图

### 4.1 本域收信

```text
SmtpHandler        MailParser       MailboxService     MetaRepo        Redis
      │ DATA完成       │                │                 │              │
      │───────────────►│ parse(流式)     │                 │              │
      │               │─ EML临时文件 ──►│                 │              │
      │               │────────────────► append(INBOX)    │              │
      │               │                 │─事务─► insert   │              │
      │               │                 │─写EML─►         │              │
      │               │                 │─发布─►──────────────────────► channel
      │ 250 OK ◄──────┴─────────────────┴─────────────────┴──────────────┘
```

### 4.2 Webmail 发信

```text
前端             MailController     MailService     Queue   已发送Repo
 │ /send           │                   │              │         │
 │───────────────► │─ compose ───────►│              │         │
 │                  │                   ├ 本域直接append│         │
 │                  │                   ├─enqueue────►│         │
 │                  │                   ├写已发送─────►│         │
 │◄── messageId ────┴───────────────────┴──────────────┴─────────┘
 │ 异步: QueueScheduler 完成外域投递
```

## 6. Web API 接口详细定义

### 6.1 统一约定

- Base URL：`/api`；鉴权 `Authorization: Bearer <access>`。
- 响应：`R<T> = { code, msg, data, timestamp }`，成功 `code=0`。
- 分页：`page`(0 基)、`size`、`sort`。
- 时间格式：`yyyy-MM-dd HH:mm:ss`（UTC+8）。

### 6.2 认证

**POST `/api/auth/login`**

```json
// 请求
{ "username": "zhangsan", "password": "******" }
// 响应 data
{ "accessToken":"...","refreshToken":"...","expiresIn":3600,
  "user":{ "id":1,"name":"张三","email":"...@example.com" } }
```

**POST `/api/auth/refresh`** — `{ "refreshToken": "..." }` → 新 token 对。
**POST `/api/auth/logout`** — 撤销会话。

### 6.3 邮件

**GET `/api/mail/folders`**

```json
// data: [{ id,name,path,unread,total,type:"INBOX|SENT|DRAFTS|TRASH|CUSTOM" }]
```

**GET `/api/mail/folders/{id}/messages?page=0&size=50&sort=date_sent,desc`**

```json
// data: { list:[{ id,subject,fromName,fromAddr,dateSent,flags,hasAttachments,preview,unread }], page,size,total }
```

**GET `/api/mail/messages/{id}`** → details：headers、bodyHtml、bodyText、attachments[]。

**GET `/api/mail/messages/{id}/raw`** → 流式 EML（`Content-Type: message/rfc822`）。

**POST `/api/mail/messages/{id}/move`** — `{ "toFolderId":5, "copy":false }`。
**POST `/api/mail/messages/{id}/flags`** — `{ "add":["FLAGGED"], "remove":[] }`。
**DELETE `/api/mail/messages/{id}`** — 逻辑删除入垃圾桶。
**GET `/api/mail/messages/{id}/attachments/{attId}`** — 附件下载流。

### 6.4 写信 / 发送

**POST `/api/mail/send`**

```json
{
  "to": ["b@example.com"], "cc": [], "bcc": [],
  "subject": "主题", "html": "<p>正文</p>", "text": "纯文本",
  "draftId": null, "attachments": [{ "id": 88, "name": "a.pdf" }]
}
```
→ `data:{ messageId }`

**POST `/api/mail/drafts`** — 保存（字段同 send，可含 draftId）。
**POST `/api/mail/schedule`** — `{ ...send, "at":"2025-03-01 09:00:00" }`。

### 6.5 通讯录 / 账户 / 搜索 / 设置 / 管理

| 方法与路径 | 说明 |
| --- | --- |
| `POST /api/contacts` / `PUT|DELETE /api/contacts/{id}` / `GET /api/contacts` | 通讯录 |

| `POST /api/contacts/import`、`GET /api/contacts/export?format=vcf` | 导入导出 |

## 7. 协议引擎状态机详细设计

### 7.1 SMTP 状态机

```text
                EHLO/HELO
  CONNECTED ───────────────► GREED
                               │  AUTH -->
                               ▼
                          AUTHENTICATED
                               │  MAIL FROM
                               ▼
                              MAIL ──RCPT──► RCPT ＋──RSET──►
                               │              │  DATA
                               ▼              ▼
                             DATA ◄───(0..N RCPT)
                               │ 收到 "\r\n.\r\n"
                               ▼
                         ACCEPTED ──250──► (QUIT→221) / 回 MAIL
```

非法命令/错误 → `5xx/4xx`；`RSET` 重置当前信封。

### 7.2 IMAP 状态机

```text
  NOT_AUTHENTICATED ──LOGIN/AUTHENTICATE──► AUTHENTICATED
                                              │ SELECT/EXAMINE
                                              ▼
                                            SELECTED
  (任一状态均可 LOGOUT → 注销)
```

- UID 语义：`UIDVALIDITY` 在文件夹创建时生成并持久化；`UIDNEXT` 每次 append 递增。
- EXPUNGE 不实际删 EML，标记 `\Deleted` 后再 `EXPUNGE` 触发物理删除。

### 7.3 POP3 状态机

```text
  AUTHORIZATION ──USER/PASS/STLS──► TRANSACTION ──QUIT──► UPDATE(实际删DELE标记)
```

### 8.3 状态管理（Pinia）

- `useAuthStore`：token、user、permissions。
- `useMailStore`：文件夹树、当前文件夹、列表、未读数、选中项、筛选。
- `useContactStore`：联系人、分组、当前选择。
- `useSettingsStore`：主题、签名、布局偏好。

### 8.4 UI 风格方向（高保真）

采用**精致邮件桌面客户端**风格，细节见 `doc/ui-prototype/` 下的高保真原型：

- 布局：左侧文件夹栏 + 中侧邮件列表 + 右侧阅读面板（三栏），支持响应式折叠。
- 色彩：以品牌蓝为主色、暖灰背景、高对比正文；未读加粗 + 蓝点。
- 字体：正文使用可读性强的中文/西文系统字体栈；数字、时间使用等宽细节。
- 交互动效：列表项 hover、删除/星标微动效、发送成功 toast。
