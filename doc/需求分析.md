## 1. 文档目的与范围

### 1.1 文档目的

本文档面向系统设计、开发、测试与部署团队，对「基于 Spring Boot + Vue 3 的邮件服务器与 Web 邮件管理系统」进行需求分析，明确系统的功能范围、性能指标、模块划分与技术边界，作为后续概要设计、详细设计与开发验收的依据。

### 1.2 文档范围

本系统包含两大组成部分：

- **邮件服务器（Mail Server）**：遵循标准邮件协议（SMTP、IMAP、POP3）的邮件收发、存储与投递引擎。
- **Web 邮件管理（Web Mail Client）**：提供常见邮件客户端功能（写信、收信、邮件管理、通讯录、搜索、组织管理等）的浏览器端管理界面。

### 1.3 不在范围内

- 不实现反垃圾邮件（Spam）与反病毒网关的深度内容过滤引擎（仅预留接口）。
- 不做 Mailbox 的分布式集群高可用强一致方案（支持单机为主的多实例横向扩展预案）。
- 不包含面向最终用户的移动端原生 App（留待后续迭代）。

## 2. 术语与缩写

| 术语 | 全称 / 说明 |
| --- | --- |
| SMTP | Simple Mail Transfer Protocol，简单邮件传输协议，用于邮件发送与服务器间投递（RFC 5321） |
| IMAP | Internet Message Access Protocol，用于邮件的远程管理与同步（RFC 3501，及 RFC 9051） |
| POP3 | Post Office Protocol Version 3，用于邮件下载（RFC 1939） |
| MTA | Mail Transfer Agent，邮件传输代理（发送/转发方） |
| MDA | Mail Delivery Agent，邮件投递代理（投递到本地信箱） |
| MUA | Mail User Agent，邮件用户代理（客户端/Web 收发界面） |
| MIME | Multipurpose Internet Mail Extensions，邮件内容编码与多部分结构（RFC 2045~2049） |
| EML | Standard for the Archieval of Internet Messages，邮件原文标准格式（RFC 822/5322） |
| SASL | Simple Authentication and Security Layer，认证扩展（RFC 4422） |
| TLS | Transport Layer Security，传输层安全（STARTTLS / SMTPS） |
| Mailbox | 邮箱目录，邮件在服务器端的存储单元 |
| Webmail | 通过浏览器访问的邮件客户端 |

## 3. 项目背景与目标

### 3.1 背景

中小企业、高校与私有化部署场景中，对自主可控、可私有化部署的邮件系统存在明确需求。市面商用邮件系统往往封闭、难以二次开发。本项目旨在以开源技术栈（Spring Boot + Vue 3）构建一套**模块化、可扩展、可私有化部署**的邮件服务器与 Web 邮件管理一体化系统，同时用于技术平台的沉淀与团队邮件技术能力的建设。

### 3.2 建设目标

- **协议兼容**：完整支持 SMTP/IMAP/POP3 标准协议，能与主流 MUA（Outlook、Thunderbird、Foxmail、手机邮箱客户端）互操作。
- **功能完整**：Web 邮件客户端覆盖主流邮件功能（收/发/管理/搜索/通讯录/多账户）。
- **模块化**：按职责拆分为服务器、存储、投递、Web 接口、前端等多个独立模块，便于维护与扩展。
- **安全可控**：支持 TLS 加密、SASL 认证（口令、OAuth 预留）、反滥用防护（限流/灰名单），数据可备份。
- **可运维**：提供系统管理、日志、监控、域与用户管理能力。

### 3.3 成功标准

- 内部邮件收发成功率 ≥ 99.9%。
- 与至少 3 款主流邮件客户端互操作通过。
- Web 端常用操作（收信、发信、搜索）在 P95 延迟内达到可用标准（见 §9）。
- 单实例可稳定服务 1 万+ 账户（以基线硬件估算）。

## 4. 总体架构

```text
+------------------------------------------------------------------+
|                        浏览器 (Vue 3 Web Client)                  |
|  收件箱/写信/邮件详情/通讯录/搜索/设置/多账户/系统管理            |
+------------------------------------------------------------------+
                          |  HTTPS / REST-JSON（Web API 网关）
+------------------------------------------------------------------+
|                     Spring Boot 后端（模块化单体 / 可拆微服务）     |
|                                                                  |
|  Web 管理模块           邮件服务模块            系统管理模块        |
|  (REST Controller)     (SMTP / IMAP / POP3)   (用户/域/配置/日志) |
|  - 会话/权限           - 协议会话处理器        - 管理员后台        |
|  - 邮件业务逻辑        - 邮件解析(MIME/EML)    - 配额与策略        |
|  - 通讯录/搜索         - 投递队列              - 监控与指标        |
|  - 公共/共享内存        - 存储抽象层            - 审计日志          |
+------------------------------------------------------------------+
                          |
              +-----------+-----------+
              |  邮件存储 (Mailbox)     |       <-- 文件系统 / 对象存储
              +------------------------+
              |  元数据存储 (RDBMS)     |       <-- MySQL/PostgreSQL
              +------------------------+
              |  缓存 / 队列 (Redis)    |       <-- 会话/限流/异步队列
              +------------------------+
```

**架构说明**

- 采用「模块化单体（Modular Monolith）」起步，模块间以清晰接口隔离；当负载上升时可将「邮件服务模块」「Web 管理模块」「系统管理模块」分别拆分为独立服务。
- 邮件协议引擎（SMTP/IMAP/POP3）自研协议会话处理器，基于 Netty 构建非阻塞网络层。
- 存储层抽象为接口，`IMailboxStore` 支持本地文件系统与对象存储（S3 兼容）两种实现。
- 前端为 Vue 3 SPA，通过 REST API 与后端交互；邮件正文/附件经二进制接口上传下载。

## 5. 干系人与使用场景

### 5.1 干系人

| 干系人 | 角色 | 主要诉求 |
| --- | --- | --- |
| 最终用户 | Webmail 使用者 | 收发顺畅、搜索快、界面友好、移动端可用 |
| 系统管理员 | 部署/运维方 | 用户/域管理、配额、日志、监控、备份恢复 |
| 外部客户端用户 | 使用第三方 MUA 的用户 | 协议标准、认证便捷、同步一致 |
| 开发/测试团队 | 建设方 | 模块清晰、易测试、可扩展 |

### 5.2 使用场景（用例概览）

1. **U1 发送邮件**：用户在 Webmail 或 MUA 中撰写邮件并发送，系统经 SMTP 投递到本域或外域。
2. **U2 接收邮件**：外部 MTA 将邮件投递到本系统，系统按收件人投递到对应 Mailbox，并写入 DB/索引。
3. **U3 阅读/管理邮件**：用户通过 IMAP 或 Webmail 读取、标记、移动、删除、归档邮件。
4. **U4 多账户管理**：用户可在 Webmail 中配置多个邮箱账户统一管理。
5. **U5 通讯录管理**：维护联系人、分组、导入导出。
6. **U6 邮件搜索**：对正文、主题、发件人、附件等进行全文检索。
7. **U7 系统管理**：管理员管理域、用户、配额、策略、查看日志与监控。
8. **U8 数据备份恢复**：管理员对邮件数据与元数据执行备份与恢复。

## 6. 邮件服务器功能需求

### 6.1 SMTP 服务（发送与投递）

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| SMTP-01 | 标准会话 | 高 | 遵循 RFC 5321 会话流程（EHLO/HELO、MAIL FROM、RCPT TO、DATA、QUIT） |
| SMTP-02 | 认证 | 高 | 支持 AUTH LOGIN / PLAIN，SASL 扩展（CRAM-MD5、OAUTH2 预留） |
| SMTP-03 | 加密 | 高 | 支持 STARTTLS 与 SMTPS（465） |
| SMTP-04 | MIME 接收 | 高 | 解析 MIME 头与多部分（multipart/alternative、related、mixed） |
| SMTP-05 | 投递判定 | 高 | 收件人为本域 → 投递本地 Mailbox；外域 → 按 MX/DNS 转发 |
| SMTP-06 | 邮件大小限制 | 中 | 可配置单封邮件大小上限（默认 25MB） |
| SMTP-07 | 退信（NDR） | 中 | 投递失败生成退信原路返回发件人 |
| SMTP-08 | 会话超时与限流 | 高 | 空闲超时、连接数限流、每分钟发送配额（防滥用） |
| SMTP-09 | 灰名单/速率控制 | 中 | 简单反垃圾机制：灰名单（greylisting）、连接频率检测 |

### 6.2 IMAP 服务（邮件远程管理）

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| IMAP-01 | 标准会话与认证 | 高 | RFC 3501 会话，LOGIN/AUTHENTICATE，STARTTLS/IMAPS |
| IMAP-02 | Mailbox 操作 | 高 | LIST / CREATE / DELETE / RENAME / SUBSCRIBE / SELECT |
| IMAP-03 | 消息操作 | 高 | FETCH / STORE（flags）/ COPY / MOVE（RFC 6851）/ SEARCH / EXPUNGE |
| IMAP-04 | 状态与标志 | 高 | \Seen、\Answered、\Flagged、\Deleted、\Draft、\Recent |
| IMAP-05 | 多路复用与 IDLE | 中 | 支持 IMAP IDLE（RFC 2177）实时推送新邮件 |
| IMAP-06 | 附件与 BODY | 高 | FETCH BODY/BODYSTRUCTURE/附件分段下载，支持断点（part ranges） |
| IMAP-07 | 配额（QUOTA） | 中 | RFC 2087 配额扩展返回用户容量信息 |
| IMAP-08 | 性能扩展 | 中 | 支持一次 GETQUOTA / 批量命令流水线（pipelining） |

### 6.3 POP3 服务（邮件下载）

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| POP3-01 | 标准会话 | 高 | RFC 1939 会话：USER/PASS、STAT、LIST、RETR、DELE、QUIT |
| POP3-02 | 加密认证 | 高 | APOP（预留）、STLS、POP3S（995） |
| POP3-03 | 下载模式 | 中 | 支持「阅读后删除」与「保留服务器副本」可配置行为 |

### 6.4 邮件解析与存储

| 编号 | 功能 | 优先级 | 说明 |
| --- | --- | --- | --- |
| MSE-01 | MIME 解析 | 高 | 解析编码（Base64/QP）、字符集（UTF-8 等）、内联/附件提取、HTML 与纯文本 |
| MSE-02 | 邮件原文（EML）存储 | 高 | 以标准 EML 格式落盘，保证可迁移/可导出 |
| MSE-03 | 去重与引用规范化 | 中 | 附件指纹去重、Message-ID 校验 |
| MSE-04 | 投递队列 | 高 | 持久化投递队列，支持失败重试与延迟发送（定时/定时发送） |
| MSE-05 | 大附件处理 | 中 | 分段存储与流式读写，避免整封邮件常驻内存 |

## 9. 非功能需求

### 9.1 性能

| 指标 | 目标 |
| --- | --- |
| 邮件发送（本域）P95 | ≤ 500 ms（不含客户端网络） |
| Webmail 列表加载 P95 | ≤ 800 ms（日均 5 万封账户 1 万邮件量） |
| 全文搜索 P95 | ≤ 1.5 s（单关键字，含附件名） |
| SMTP 并发连接 | 支撑 ≥ 1 000 并发会话 |
| IMAP 并发连接 | 支撑 ≥ 2 000 并发会话 |
| 单实例账户容量 | ≥ 1 万账户（基线 8C16G 服务器） |

### 9.2 可用性与可靠性

- 服务可用性目标 ≥ 99.9%。
- 邮件送达采用「至少一次」投递语义，队列持久化，进程重启不丢队列。
- 存储层支持断电恢复与一致性校验（EML 完整性）。

### 9.3 可扩展性

- 邮件服务、Web 管理、系统管理模块可独立水平扩展。
- 存储层可插拔（文件系统 / 对象存储）。
- 认证方式可插拔（口令 / LDAP / OAuth2，预留）。

### 9.4 可维护性

- 模块化代码与统一日志（结构化日志）、统一异常体系。
- API 遵循 OpenAPI 规范，自动生成接口文档。
- 提供健康检查与启动自检。

### 9.5 安全

见 [§13 安全需求](#13-安全需求)。

### 9.6 兼容性（浏览器）

- 支持主流现代浏览器：Chrome ≥ 100、Edge ≥ 100、Firefox ≥ 100、Safari ≥ 15。

## 10. 模块划分与技术选型

### 10.1 后端模块（Spring Boot）

| 模块 | 职责 | 说明 |
| --- | --- | --- |
| `mail-server-core` | 邮件解析、EML 模型、投递队列、工具 | 无协议依赖的可复用核心 |
| `mail-protocol-smtp` | SMTP 协议会话处理器（Netty） | 接收/投递 |
| `mail-protocol-imap` | IMAP 协议会话处理器（Netty） | 远程管理 |
| `mail-protocol-pop3` | POP3 协议会话处理器（Netty） | 下载 |
| `mail-storage` | Mailbox 存储抽象与实现 | 文件系统 / 对象存储 |
| `mail-web-api` | REST 控制器、业务服务、会话/权限 | 前端对接 |
| `mail-admin` | 系统管理域/用户/配额/策略 | 管理员接口 |
| `mail-common` | 配置、安全、日志、缓存、工具 | 通用 |
| `mail-index` | 全文索引（Elasticsearch/Lucene，预留） | 搜索 |

技术要点：`spring-boot-starter-web`、`spring-boot-starter-security`、`spring-boot-starter-data-jpa`、`netty-handler`、`spring-boot-starter-data-redis`、`flyway`。

### 10.2 前端模块（Vue 3）

| 模块 | 职责 |
| --- | --- |
| `web-mail-client` | 邮件客户端主界面（收/发/管理/搜索/通讯录/设置） |
| `web-admin` | 系统管理后台（域/用户/配额/日志/监控） |
| `web-common` | 通用组件、请求封装、主题、国际化 |

技术要点：`vue@3`、`vite`、`pinia`、`vue-router`、`element-plus`（或 `arco-design`）、`axios`、`@vueuse/core`、`vuedraggable`（拖拽）。

### 10.3 部署形态

- 发包方式：前端构建静态资源由 Spring Boot 静态资源托管（或 Nginx）。
- 可选容器化：Docker Compose（Spring Boot + MySQL/PostgreSQL + Redis + 可选 ES）。

## 11. 数据模型初步设计

### 11.1 关系数据库（元数据）核心表

| 表 | 关键字段 | 说明 |

### 11.2 邮件原始存储

- 采用标准 EML 文件，路径规则示例：`{root}/{domain}/{user}/{mailbox}/{uid}/{message-id}.eml`。

### 11.3 缓存

- Redis：登录会话、SMTP 限流计数器、灰名单、实时新邮件通知。

## 13. 安全需求

| 类别 | 需求 |
| --- | --- |
| 传输安全 | 邮件协议与 Web 均启用 TLS；密码不以明文传输 |
| 认证 | 密码加盐哈希（BCrypt）；支持两段式 OAuth2 与 LDAP 接入（预留） |
| 授权 | 基于角色的访问控制（ROLE_USER / ROLE_ADMIN）；接口级权限校验 |
| 会话 | 令牌过期与刷新；登录失败限流；异地登录提示（预留） |
| 数据安全 | 外部账户口令可逆加密存储（主密钥分离）；敏感配置脱敏 |
| 反滥用 | SMTP 连接/频率限流；灰名单；发件人域校验；SPF/DKIM/DMARC 签名（预留） |
| 防注入 | 参数校验与防注入；HTML 邮件渲染前消毒（防 XSS） |
| 审计 | 管理员关键操作留痕，日志保留策略 |

## 14. 约束与假设

### 14.1 约束

- 采用 Java 17 + Spring Boot 3.x、Vue 3 + Vite 技术栈，全栈模块化单体起步。
- 数据库默认 MySQL 8 / PostgreSQL 14（通过 JPA 兼容）。
- 自研协议引擎，不引入重型第三方 MTA 的强耦合。

### 14.2 假设

- 初始部署以单实例为基准，多实例为后续演进。
- 外部 OAUTH 提供方、LDAP、Elasticsearch 非首期必需（预留下沉）。

## 16. 风险分析

| 风险 | 等级 | 应对 |
| --- | --- | --- |
| 自研 IMAP 同步一致性问题（UID 变更） | 高 | 严格按 RFC 实现 UIDVALIDITY/UIDNEXT，建立互操作测试矩阵 |
| 协议对第三方客户端兼容不足 | 高 | 早期引入主流 MUA 回归测试，预留扩展点 |
| 大附件/高并发导致内存压力 | 中 | 流式读写、分段存储、连接与配额限流 |
| 数据丢失（读写异常） | 中 | EML 落盘原子写、队列持久化、定期备份 |
| 反垃圾能力有限 | 中、提醒 | 首期灰名单/限流，后续接入内容过滤网关 |
