# Web 版邮箱客户端需求分析文档

> 版本：v1.1（已确认关键决策）  
> 拟采用技术栈：Spring Boot（后端）+ Vue 3（前端）  
> 数据存储：每用户独立存储文件（OST 格式，导出为 PST 供 Outlook 读取）

---

## 1. 引言

### 1.1 编写目的

本文档用于明确《Web 版邮箱客户端》的完整需求，作为后续概要设计、详细设计、开发、测试及验收的依据。主要内容包括：项目背景与目标、业务范围、功能需求、非功能需求、存储与兼容性约束、技术选型建议、风险与开放问题。

### 1.2 项目背景

企业/个人需要一套 **纯 Web 方式访问的邮箱客户端**，用于代替或补充桌面 Outlook，同时希望：

- 每个注册用户拥有**独立**的本地存储文件（**.ost**），便于按用户隔离与迁移。
- 存储格式尽量**兼容 Microsoft Outlook（.ost / .pst）**，便于数据迁移、备份与二次使用。
- 支持当前主流邮件收发协议与加密方式。
- 支持**文件夹管理**与**邮件规则（Rules）**。

### 1.3 术语与缩略语

| 术语 | 说明 |
| --- | --- |
| OST | Offline Storage Table，Outlook 的离线存储文件格式（.ost） |
| PST | Personal Storage Table，Outlook 的个人存储文件格式（.pst） |
| SMTP | Simple Mail Transfer Protocol，邮件发送协议，端口 25/465/587 |
| POP3 | Post Office Protocol 3，邮件接收协议，端口 110/995 |

| SSL/TLS | 安全套接字层/传输层安全 |
| STARTTLS | 在明文端口上通过命令升级为 TLS 的机制 |
| SASL | Simple Authentication and Security Layer，简单认证与安全层 |

## 2. 项目目标与范围

### 2.1 总体目标

构建一套基于 **Spring Boot + Vue 3** 的 Web 邮箱客户端，具备：

1. **多用户隔离**：每个用户在服务端拥有独立的 OST 存储文件。
2. **Outlook 兼容**：OST 作为本地工作存储；支持**导出为 PST** 供 Outlook 直接打开读取（Outlook 单向读取为主要兼容目标）。
3. **全协议适配**：支持 IMAP4、POP3、SMTP 等主流收发协议及对应加密方式（**明确不包含 Exchange**）。
4. **完整邮件能力**：读写、附件、草稿、已发送、回收站、文件夹及规则。
5. **实时推送**：通过 WebSocket / IMAP IDLE 实现新邮件实时到达通知。
6. **附件双态存储**：支持**服务器本地文件系统**与 **MinIO 对象存储**两种附件存储方式。
7. **离线可用**：以 PWA 形式提供离线访问与缓存浏览。
8. **安全可控**：传输加密、认证、鉴权、数据加密与审计。

### 2.2 业务范围

| 在范围内 | 不在范围内 |
| --- | --- |
| 多用户注册、登录、账户管理 | 邮件服务器（SMTP/IMAP/POP3 服务端）本身 |
| 每用户独立 OST 存储 | Exchange Server 的部署与运维（**不做 Exchange 接入**） |
| IMAP/POP3/SMTP 接入 | 即时通讯/聊天 |
| 邮件收发、文件夹、规则、搜索 | 全文检索引擎的分布式与集群建设（可选扩展） |
| OST 作为工作存储，导出为 PST 供 Outlook 读取 | 与 Outlook 双向实时同步（不在本期范围） |
| 附件本地文件系统与 MinIO 双存储 | 移动端原生 App（以 PWA 响应式支持） |
| 实时推送（WebSocket / IMAP IDLE） | 组织域控（AD）深度集成（预留） |
| PWA 离线访问 | |

## 3. 用户场景与核心流程

### 3.1 典型用户场景

1. **首次接入邮箱**：用户登录系统 → 输入邮箱账号/密码或授权码 → 选择协议（IMAP/POP3）→ 系统校验并创建该用户的独立 OST 存储 → 首次同步邮件索引。
2. **日常收发邮件**：用户在 Web 端阅读、编写、回复、转发邮件；系统通过 SMTP 发送，通过 IMAP/POP3 拉取收件箱，新邮件通过 WebSocket **实时到达**。
3. **离线/断网浏览（PWA）**：用户断网后可浏览已同步的邮件与已缓存附件；恢复在线后自动重新同步与刷新。
4. **导入 Outlook 数据**：用户上传 .pst 文件，系统解析并入本地用户存储。
5. **应用规则**：用户创建规则（如将发件人 X 的邮件移动到文件夹 Y），服务端按规则对收到的邮件自动处理。
6. **导出供 Outlook 读取**：用户/管理员将邮件导出为 .pst 文件，可用 Outlook 直接打开读取。
7. **管理员配额管理**：管理员为不同用户配置存储上限与附件存储方式，超限提醒。

### 3.2 核心时序流程（发送邮件）

```
用户(Web) -> 后端API -> OST存储服务 -> SMTP客户端 -> SMTP服务器
   1. 前端提交邮件(收件人/主题/正文/附件)
   2. 后端校验、加入发送队列
   3. 通过 SMTP(SSL/TLS/STARTTLS) 发送
   4. 发送成功 -> 写入"已发送"到用户 OST
   5. 失败 -> 加入失败队列，重试，写错误日志
```

### 3.3 核心时序流程（接收邮件 - IMAP）

```
后端 IMAP IDLE 长连接任务 -> 新邮件到达 -> 写入用户OST -> 触发规则 -> WebSocket推送前端刷新
（IDLE 不可用时降级为定时轮询）
```

## 5. 数据存储设计约束

### 5.1 每用户独立 OST 文件

- 系统为每个用户在主存储根目录下创建独立子目录，如 `storage/{userId}/mail.ost`。
- OST 文件封装邮件对象模型（文件夹、消息、附件、规则、配置）。
- 通过文件锁（分布式场景下按用户加锁）保证并发读写一致。
- 数据访问统一封装为 **OST 存储服务**，避免业务代码直接操作文件。

### 5.2 OST 格式与 Outlook 兼容性说明

- **存储目标**：OST 作为**服务端工作存储**，承载邮件对象模型（文件夹、消息、附件、规则、配置），是系统内部读写结构。
- **兼容目标（已确认）**：**仅单向导出为 PST 供 Outlook 读取**，不要求与 Outlook 双向实时同步。即系统负责「写入→OST 工作存储→导出为标准 PST」，Outlook 通过 .pst 打开读取。
- **兼容策略**：
  1. 字段名与 MIME 头遵循 RFC 规范（5322、2045~2049、3501 等）。
  2. 提供 PST 导出工具（生成标准 .pst 结构），通过标准库或自研序列化器保证 Outlook 可打开。
  3. 支持 PST 导入解析。
  4. 编制 **兼容性矩阵**，按 Outlook 版本（2013/2016/2019/365）验证导出文件的打开与读取。
- **注意**：微软未公开完整的 OST/PST 私有二进制规范。因为本期**以导出为 PST 供 Outlook 读取为主**，复杂度较双向同步大幅降低，通常采用「语义兼容 + 标准 PST 导出层转换」方案即可满足。具体开源库（如 libpst / Java PST 解析器）的选用在概要设计阶段完成 POC 验证。

> 说明：需求阶段将结论定位为**单向导出兼容**，具体落地策略在技术选型与概要设计细化。

### 5.3 数据库设计建议（元数据层）

| 表/概念 | 说明 |
| --- | --- |
| User | 用户、密码哈希、MFA |
| MailAccount | 账户绑定、协议、服务器、端口、凭据引用 |
| Folder | 文件夹层级、与 OST 的映射 |
| Message(摘要) | 用于快速列表/搜索的摘要索引（正文存在 OST） |
| Rule | 规则定义 |
| SyncJob / SyncLog | 同步任务与日志 |
| AttachmentMeta | 附件元数据、存储类型（本地/MinIO）、存储路径/桶与对象键 |

> 架构上通常「关系型 DB 存元数据与索引 + OST 存全量邮件对象」二者并用。

### 5.4 附件存储（双模式，已确认）

附件支持两种可配置存储方式：

| 方式 | 说明 | 适用场景 | 优先级 |
| --- | --- | --- | --- |
| 本地文件系统 | 附件保存于服务器指定目录（按用户/邮件分目录） | 单机/中小规模、内网 | P0 |
| MinIO 对象存储 | 附件上传至 MinIO 桶，元数据记录桶与对象键 | 分布式/大容量/云化 | P0 |

- 两种方式通过统一的 **附件存储抽象接口** 提供，系统按全局或按用户的配置切换。
- 下载/预览通过后端生成预签名 URL 或受控流式接口，不直接暴露后端路径。
- 导出为 PST 时，把所引用的附件内容一并打包进导出文件。

## 6. 非功能需求

### 6.1 性能

| 项 | 指标 | 优先级 |
| --- | --- | --- |
| 邮件列表加载 | P95 < 2s（万级邮件） | P0 |
| 邮件搜索 | 常规关键字 < 3s（需索引），全文可异步 | P1 |
| 并发 | 单机支撑 500+ 活跃用户，可水平扩容 | P1 |
| 同步 | IMAP IDLE 实时推送；IDLE 不可用时降级轮询（可配置 1~5 分钟） | P0 |
| 实时推送时延 | 从服务器新邮件到 Web 端可见 ≤ 5s（IDLE 生效） | P0 |
| WebSocket 连接 | 支持断线自动重连与心跳保持 | P0 |
| PWA 离线缓存 | 离线会话可浏览已同步邮件与已缓存附件，在线自动恢复同步 | P0 |

### 6.2 可用性

- 服务可用性 ≥ 99.5%。
- 单点故障恢复：OST 损坏检测与重建、定时备份。

### 6.3 安全性

- 传输：全站 HTTPS；与上游服务器使用 TLS/STARTTLS。
- 存储：密码加盐哈希（BCrypt/Argon2）；OST 可选静态加密（AES-256）。
- 认证：会话令牌、OAuth2、可选 MFA。
- 授权：RBAC，用户仅能访问自己的 OST。
- 内容安全：HTML 邮件清洗防 XSS，附件 AV 扫描（可选）。
- 审计：登录、收发、规则、导入导出可审计。

### 6.4 可维护性

- 分层架构（展示层/接口层/业务层/协议层/存储层）。
- 模块化、可插拔协议适配（IMAP/POP3/SMTP 独立模块，附件存储本地/MinIO 可插拔）。
- 统一日志与指标（接入监控）。

### 6.5 兼容性

- 浏览器：Chrome、Edge、Firefox、Safari 最新两个大版本。
- 响应式：适配桌面与移动端浏览器。
- **PWA**：支持安装到桌面，离线可用；导出 .pst 文件可用 Outlook 2013/2016/2019/365 打开读取。

### 6.6 可扩展性

- 支持横向扩容（无状态 API + 共享存储/分布式存储）。
- OST 存储可迁移到对象存储/网络盘。
- 预留企业版（AD 集成、多租户）。

```
+----------------------------------------+----------------------------------------+
                                          | REST / WebSocket (推送)
+----------------------------------------v----------------------------------------+
|                         Layer: 接口层 (Spring Boot REST API)                     |
+----------------------------------------+----------------------------------------+
| 业务层: 用户服务 | 账户服务 | 邮件服务 | 文件夹服务 | 规则引擎 | 搜索服务 | 导入导出 |

```

## 8. 风险与开放问题

| 编号 | 风险/问题 | 影响 | 建议处置 |
| --- | --- | --- | --- |
| R-1 | OST/PST 为私有二进制格式，微软未公开完整规范 | 导出文件兼容性有不确定性 | 因本期为**单向导出 PST 供 Outlook 读取**，采用语义兼容 + 标准 PST 导出层；在概要设计选用经验证的 Java PST 读写库并做 POC |
| R-2 | 多用户大量 OST 并发 I/O 与扩容 | 存储/I/O 瓶颈 | 按用户分片、文件锁；附件可放 MinIO 分流 |
| R-3 | 规则执行与同步顺序一致性 | 规则可能漏触发/重复执行 | 幂等设计、状态记录、失败重试 |
| R-4 | IMAP IDLE 连接稳定性 | 长连接易断、占用连接数 | 心跳保活、IDLE 超时重连、降级轮询 |
| R-5 | HTML 邮件 XSS / 附件安全 | 安全问题 | 内容清洗、沙箱预览、AV 扫描 |
| R-6 | 静态加密 OST 影响性能/兼容 | 性能与可移植性 | 分层加密策略与配置开关 |
| R-7 | 本地文件与 MinIO 双存储的路径/一致性 | 附件管理复杂度 | 统一附件抽象接口，Migration 工具支持切换 |

### 关键决策（已确认）

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| D-1 | Outlook 兼容深度 | **仅单向导出为 PST 供 Outlook 打开读取**，不做双向实时同步 |
| D-2 | 推送方式 | **实时推送**（IMAP IDLE + WebSocket）；IDLE 不可用时降级轮询 |
| D-3 | Exchange | **不支持**，仅支持 IMAP/POP3/SMTP |
| D-4 | 附件存储 | **服务器本地文件系统 + MinIO 两种**，通过抽象接口可配置切换 |
| D-5 | 离线能力 | **需要 PWA** 离线访问与缓存 |

## 9. 验收标准（建议草案）

1. 支持用户注册登录、多账户绑定，每用户拥有独立 OST 存储文件，且互不可见。
2. 支持 IMAP/POP3 接收、SMTP 发送，支持 SSL/TLS 与 STARTTLS。（不涉及 Exchange）
3. 支持邮件列表/详情/编写/回复/转发/附件/搜索/标志/草稿。
4. 支持文件夹 CRUD 与规则的创建、启停、执行（移动到文件夹、标记已读等）。
5. 支持 PST 导入，以及**导出为 PST 且能被 Outlook（2013/2016/2019/365）打开正常读取**。
6. 新邮件通过 **WebSocket + IMAP IDLE 实时到达**，推送时延 ≤5s；断线自动重连，IDLE 不可用时降级轮询。
7. 附件可配置存储于**服务器本地文件系统**或 **MinIO**，两种方式可切换且不影响上传/下载/预览。
8. **PWA 已安装**，离线时可浏览已同步邮件与已缓存附件，在线后自动恢复同步。
9. 满足第 6 章非功能指标（性能、安全、可用性）。
